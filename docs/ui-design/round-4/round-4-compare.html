发现页：三处结构性改动的前后对照

同一演示数据、同一浏览器（Playwright Chromium）、同一设备壳。实验按 E1 → E2 → E3 顺序叠加；E2 对照基线，E3 对照 E2 阶段，避免把后一项改动的效果误记到前一项上。

Experiment 01

先看未来，再看过去

默认列表不再以已结束 / 已取消活动开场；置顶活动不再在首屏重复三次。

首行：10/11 已结束 → 10/25 青城后山 a1 赵公山：3 次 → 2 次（E1 阶段，横滑仍在） 过去组置底：10/12 → 10/11 计数：8 场 · 置顶已在上方

结论：保留。默认视图的信息顺序从「过去 → 未来」改为「未来 → 过去」，首屏无需越过两条已结束记录；去重规则只在默认视图生效，筛选 / 搜索仍返回完整结果集。

Experiment 02

主卡不再叠压，首屏先看到行动

白卡压图 24px 改为图下纸面；刊头压缩；距离 / 爬升 / 领队 / 费用与余位重新分组。

375 CTA：693–741 → 616–664（视口 667） 刊头：146 → 123 白卡信息板：337 → 0（图下纸面） hero 标题：30 → 24

结论：保留。叠压没有承担额外信息，只把 CTA 推离首屏；图下纸面保留编辑感，同时让主卡从「海报」回到「可行动的活动入口」。

Experiment 03

去掉没有承担发现任务的横滑轨

横滑 3 张与主卡、下方列表重复；移除后页面明显缩短，接缝筛选提前进入视野。

横滑区：272 → 0 390 全页截图：2104 → 1784（截图高度） 列表起点：1264 → 850 a1 全页出现：2 → 1

结论：保留删除。横滑区没有提供主卡与列表之外的新信息，却把真正的筛选 / 列表推迟约 414px；删除后「主卡 → 接缝 → 索引」成为一条连续路径。

Final

最终三视口

375 / 390 / 414 首屏：CTA 完整可见，无横向溢出；向下滚动后接缝带吸顶。

dom-check：38 PASS / 0 FAIL 0 console errors CTA：375 616–664 / 390 625–673 / 414 638–686

回归：默认列表 8 条（去重 a1）；筛选：全部 9 / 可报名 5 / 已成行 2 / 已结束 2；搜索「牛背山」1 条、无结果进入空态；加载 / 错误 / 禁用 / 空态均可达；其他版式仅做轻量一致性检查（0 溢出、0 console errors，外壳标识已切到 Round 4）。
