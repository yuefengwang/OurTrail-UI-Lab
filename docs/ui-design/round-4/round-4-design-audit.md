## 2.1 页面构图

### C1（P0）索引的默认顺序与用户决策顺序相反
- **现象**：默认「全部」列表以 10/11「已结束」、10/12「已取消」两场开头，第一场可报名活动要往下第三行才出现。
- **影响**：发现页的首要问题是「现在能报什么名、最近何时出发」。首屏之后的第一个索引屏被死内容占据，用户会先读两行无效信息，再判断页面是否还有价值。这不是「按出发时间」的错，而是**把过去与未来混在同一个升序轴**上。
- **证据**：`baseline/hybrid-390-seam.png`、`baseline/hybrid-390-mid.png`；measure 输出 rows 顺序。
- **判断**：信息组织问题，不是字号/颜色问题；应重排分组，而不是调 CSS。

### C2（P0）同一活动在首屏动线中重复三次，索引被「预览」稀释
- **现象**：a1 同时出现在主卡、横滑第 1 张、列表第 3 行；a2/a3 各出现两次。横滑区与列表前 3 项完全重叠。
- **影响**：首屏到索引之间没有获得任何新信息，却多付了 272px 滚动成本；用户会感觉页面在自我重复。Round 3 已确立「默认视图去重置顶项」的过滤语义，但 Hybrid 未执行——这是**规则落地缺失**，不是新风格问题。
- **证据**：measure 输出 `dupCount`；`baseline/hybrid-390-full.png` 可直观看到三处同题。

### C3（P0）首屏由白色信息板主导，主图没有成为第一视觉重心
- **现象**：390 首屏中主图 219px、白色信息板 337px；信息板面积约为图片的 1.5 倍，且带 1px 边框和 24px 负边距叠压，读起来是「一张卡片压在图上」，而不是「一张图进入正文」。
- **影响**：白色面板的边缘、陶土「距出发 1 天」和绿色状态词先于山脊照片被看到；「叠压」没有改善图文关系，只制造了一个悬浮卡片。用户要求重新审视 24px 叠压——实测支持**取消叠压或重构图文关系**。
- **证据**：`baseline/hybrid-390-fold.png`；measure 的 panel/media 高度。

### C4（P1）375 首屏主 CTA 完全不可见
- **现象**：375 视口 667 高，CTA 位于 693–741，主行动被截在首屏之外；信息板也被截断在事实行。
- **影响**：最小目标机型上，用户看完首屏仍不知道「下一步能做什么」；「查看安排」是页面的主行动，却要靠滚动才发现。
- **证据**：`baseline/hybrid-375-fold.png`；measure `cta.bottom = 741 > 667`。

### C5（P1）横滑轨 272px，价值低于成本
- **现象**：3 张 160px 卡只露出约 2.2 张；标题重复；「向左滑」是操作性提示，与右侧「10/18–10/26 · 3 场」同日争抢一行。3 场「本周出发」在纵向索引里本可以一次看全。
- **影响**：横滑没有提供比纵向列表更快的信息（卡片甚至缺少距离/爬升），却占用 272px 并把比较区推到首屏后 420px；对只有 9 场活动的产品，这是**为机制而机制**。
- **证据**：`baseline/hybrid-390-rail.png`；measure `rail.h = 272`、`railTitles = [a1,a2,a3]`。

### C6（P2）刊头占用 146px 且自我重复
- 「发现 · 先看，再挑」与下一行大标题「发现」重复；导语是统计句（15px），占据叙事位置却没有叙事价值。顶部还有胶囊/状态栏 64px，主图要到 y=242 才开始。
- **影响**：首屏可用高度被压缩到 602px（844-64-146-32 margin），直接放大了 C4。

### C7（P2）接缝带吸顶 134px，与页签「全部 9」重复表达
- 吸顶后占 16% 屏高；标题行「全部活动 按出发时间」和下一行页签「全部 9」表达同一件事。长列表浏览时固定区可以更轻。

## 2.2 排版工艺

### T1（P1）标题层级由位置驱动，而非信息重要性
- 页面标题「发现」30px 衬线；主卡标题 20px 衬线；横滑卡标题 14px 衬线；列表标题 14px 无衬线。
- 同一场 a1 在三个位置以三种字号出现，但主卡标题并不比列表标题明显更重要（20 vs 14）；衬线在 30/20/14 三个尺度反复使用，编辑感被摊薄。
- **影响**：读者无法用字号建立「主角—次要—索引」的稳定层级；页面显得每块都在争当主角。规则本身（「衬线只给叙述主体」）没错，错在**同一叙述主体被拆成多个尺度**。

### T2（P1）事实行语义重叠、断行不自然
- 主卡事实 7 项在 390 折成两行：第一行「距离 / 爬升 / 难度 / 领队」，第二行「名额 24 / 集合 22:10 / 剩 7 位」。
- 「名额 24」与「剩 7 位」是同一语义的两个侧面，却分置两行；「集合 22:10」已由图上 stamp（明晚 22:10 出发）表达，重复占用黄金信息位。
- **影响**：读者需要拼接两行才能得到「7/24 余位」这一关键事实；费用信息在发现页完全缺失（用户验收问题包含费用）。

### T3（P2）列表日期轴的「明晚 出发」折行
- 34px 轴宽内「明晚 出发」被拆成两行，日期列从 2 行变 3 行；a1 行因此与相邻行的基线不齐。
- **影响**：日期轴是索引的节奏骨架，第三行小字破坏了整齐感；紧迫信息更适合放在标题行或右列，而不是塞进轴内。

### T4（P2）右列三行微字 + 四种语义色 = 彩色噪点
- 60px 右列同时堆「状态词 / 名额 / 领队」三行 11–12px；状态色绿、红、蓝、棕交替出现，与「纸面 + 单一陶土强调」的克制配色冲突。
- **影响**：右列本应快速回答「能否报名」，现在需要逐行读；颜色承担了过多语义，反而降低了品牌感。
- **说明**：状态词语义色是 Round 3 冻结规则，本轮不推翻；先记录，优先通过秩序而非改色解决。

### T5（P3）数字与单位格式不统一
- `1,180 m 爬升`（千分位 + 英文单位）、`18.6 km`、`剩 7 位` 混排。
- **影响**：细节可信度；留待后续统一，不影响本轮结构决策。

## 2.3 图片与内容关系

### I1（P1）同一张图在三个容器里以三种比例连续出现
- a1 的 `cover-ridge.jpg` 先以 16:9 主图出现，再以 4:3 横滑卡出现，再以 1:1 缩略出现；原图 720×450，1:1 中心裁切把山脊主体切掉，只剩岩石局部。
- **影响**：读者会把「同图重复」读成没有更多内容；缩略图失去「识别活动」的功能，退化为「有图」的装饰。

### I2（P2）1:1 中心裁切不保留横向构图主体
- 720×450 → 64×64 的 cover 裁切丢弃左右各约 35% 画面；a2 缩略只剩树丛，a4 只剩雪坡局部。
- **影响**：列表的图片列无法帮助识别路线/地貌；但这是低风险 P2，可与缩略比例/焦点一起在下一轮处理。

### I3（P2）主图的压暗梯在叠压处被面板截断
- 图片底部渐变本来用于压字，但白色面板从图片底部上方 24px 开始覆盖，渐变在面板上沿突然结束；stamp 文字贴面板上沿仅约 20px。
- **影响**：一旦取消卡片叠压，这个断层自然消失；若保留叠压则需重新处理。

## 2.4 组件与页面整体关系

### G1（P1）四种容器语言同时出现：白卡（主卡）+ 白卡（横滑）+ 石带（接缝）+ 发丝线行（列表）
- 每块单独看都工整，合起来像「组件各精致、整体拼装」；页面缺少统一的「纸面—图—文字」关系。
- **影响**：成熟产品的页面通常只有 1–2 种容器语言；Hybrid 需要收敛为「通栏图 + 纸面文字 + 一条接缝 + 行列表」。

### G2（P1）主按钮位于可点整卡内部，且与状态词同行竞争
- 整张主卡 `role=button`，内部又有一个 span 样式的按钮；视觉上 CTA 与右端「报名中」拉成一条两端对齐的动作行，注意力被分成两半。
- **影响**：动作不唯一，点击语义也重复；应让 CTA 成为唯一动作，状态词回到元信息位置。

### G3（P2）接缝带可压缩
- 134px 的固定带在长列表中过于厚重；吸顶后只需保留搜索 + 页签 + 计数，标题行可隐藏/收紧。

### G4（P3）脚注与底部留白正常
- 页尾 64px 脚注 + 40px 页面底距；无异常拥挤或空白。

## 3. 核心机制复审（结论以实验截图为准）

### 3.1 叠压信息板
- 假设：24px 叠压没有让图文更整体，反而制造悬浮卡片感，并让面板高度（337px）压过图片（219px）。
- 实验：取消白卡与叠压，改为「通栏图 + 图上 meta + 图下纸面文字」；保留信息完整性。对比 390/375 首屏。
- 判定标准：第一眼是否先看到图；CTA 在 375 是否完整可见；信息是否仍能一眼扫完。

### 3.2 近期活动横滑轨
- 假设：3 场活动用横滑是负价值——重复主卡与列表、隐藏第 3 张、占用 272px。
- 实验：移除横滑区，让接缝带与索引直接承接主卡；upcoming 信息由索引首屏与主卡承担。
- 判定标准：首屏之后的信息是否更快到达；页面是否失去必要的「发现层」；是否出现新的视觉断层。

### 3.3 吸顶接缝带
- 假设：吸顶本身有价值（长列表随时可筛），但 134px 过重、标题行与页签重复。
- 本轮保留 sticky，仅做轻量收敛（计数合并提示，标题行保留；不做折叠交互，避免引入未验证机制）。是否进一步压缩留待真机验证。

## 4. 三项针对性实验（选择依据）

选择标准：同时影响「第一眼质量」「信息效率」「品牌气质」，且能通过结构/比例/信息组织解决，而不是增加装饰。

| 实验 | 对应问题 | 改动性质 | 预期结果 |
|---|---|---|---|
| **E1 索引相关性** | C1、C2、T3 | 信息组织（JS 分组/排序/去重） | 默认列表以可报名活动开场；置顶不重复；已结束/已取消归入末尾独立分组 |
| **E2 首屏构图** | C3、C4、C6、T1、T2、G2 | 页面结构 + 排版比例 | 图片成为第一重心；信息板去卡片化；375 首屏可见 CTA；事实行语义合并（余位/费用） |
| **E3 横滑轨职责** | C5、C2、I1、G1 | 机制取舍 | 移除重复的横滑区，页面收敛为「主卡—接缝—索引」两段节奏 |

每项实验均保留：当前版本截图、改进方案、修改理由、实际渲染截图、对比结论（见 `round-4-decisions.md`）。

## 5. 本轮不做 / 留待下一轮

- 不重写详情、协作、天气页；仅在发现页定稿后做一次导航与设计语言一致性检查。
- 不改状态词色彩体系（Round 3 冻结规则）；右列降噪只通过信息顺序与字号处理。
- 不做真机/微信开发者工具验证；sticky、触控、字体回落仍在未验证清单。
- 不调整 1:1 缩略裁切策略（需要逐图焦点标注，属于下一轮图片工艺）。
- 不新增第八套风格；Editorial / Curated 原样保留在 `prototype/round3/` 作为对照。
