## 1. 结论摘要

1. **信息顺序**：默认列表从「已结束 / 已取消开场」改为「未来活动升序 → 过去组置底」；置顶活动只在主卡出现，默认列表 8 条，计数注明「置顶已在上方」。
2. **首屏构图**：主卡取消白卡压图，改为图下纸面；刊头 146→123；375 首屏 CTA 从 693–741（被 667 视口截断）变为 616–664（完整可见）。
3. **机制取舍**：移除 272px 横滑轨，页面收敛为「主卡 → 接缝筛选 → 索引」；`.page` scrollHeight 约 2184→1736（−448），列表起点 1264→850，a1 全页出现 3 次→1 次。
4. 三项改动均来自真实渲染测量与截图对照，不以 CSS 声明值作为视觉质量证据。筛选 / 搜索仍返回完整结果集；默认视图才执行去重。

## 3. 实验 1 — 先看未来，再看过去

### 当前版本
默认「全部」列表按日期混合排序，过去活动（10/11 已结束、10/12 已取消）排在最前；a1 赵公山同时出现在主卡、横滑第 1 张、列表第 3 行；日期轴为三行（月/日/时间 + 「明晚 出发」第三行）。

### 改进方案
- 新增 `isPast()` / `defaultGroups()`：默认视图把未来活动按出发时间升序排列，过去活动独立为「已结束与已取消」组置底，组内近者先。
- 默认视图（`filter === 'all' && !q`）从列表移除 hero 活动；计数改为「8 场 · 置顶已在上方」。
- 过去组标题与行标题使用 `--r3-ink-2` 弱化；日期轴删掉第三行。
- 筛选 / 搜索视图保持完整结果集（含 hero），避免查询结果被去重规则改变。

### 修改理由
首屏最重要的问题是「先看到什么」。已结束 / 已取消活动不是本轮发现任务，却占据了列表开头；同一活动重复三次既浪费首屏，也让「置顶」失去意义。把过去放到末尾、只在默认视图去重，能让首屏直接进入「下一场可出发的活动」，同时不牺牲筛选 / 搜索的完整性。

### 实际渲染
- 默认列表顺序：a2 青城后山 10/25 → a3 巴郎山 10/26 → a4 四姑娘山 11/1 → a5 龙泉山 11/8 → a6 峨眉山 11/15 → a7 牛背山 11/22 → 过去组 a9 小鱼洞 10/12（已取消）→ a8 铁瓦殿 10/11（已结束）。
- 重复计数：E1 阶段 a1 3→2（横滑仍在）、a2 / a3 2→1；E3 后 a1 全页 1 次。
- 证据：[E1 前后对照](./round-4-compare-e1.png)；[基线全页](../../../prototype/round4/screenshots/baseline/hybrid-390-full.png)；[E1 后全页](../../../prototype/round4/screenshots/after-e1/hybrid-390-full.png)。

### 对比结论
**保留。** 默认视图的信息顺序从「过去 → 未来」改为「未来 → 过去」；首屏无需越过两条已结束记录。去重只在默认视图生效，筛选 / 搜索仍返回完整结果集。

## 4. 实验 2 — 主卡不再叠压，首屏先看到行动

### 当前版本
主图下沿叠压 24px 白卡；白卡内边距 24px，信息板 337h；375 首屏 CTA 693–741 被 667 视口截断；刊头三行 146h；hero 标题 30px；facts 两行，余位与时间分散。

### 改进方案
- 取消 `.hy-hero__panel` 白卡，改为 `.hy-hero__body` 图下纸面（`margin: 12px page-x 0`）；stamp 移到底部 16px。
- 刊头：kicker 改「先看，再挑」，导语改 12px「成都周边 · 9 场活动 · 按出发时间」，高度 146→123。
- hero 标题 30→24px；「距出发 1 天 · 余位 7 / 24」进入 kicker 行；facts 收为距离 / 爬升 / 领队 / AA ¥60 一行。
- CTA 行 margin / padding 12→8，保证 375 首屏完整可见。

### 修改理由
叠压没有承担额外信息，只把 CTA 推离首屏；白卡让主卡更像海报而不是可行动的活动入口。图下纸面保留编辑感与信息层级，同时让「图 → 标题 → 事实 → 行动」成为连续的阅读路径。

### 实际渲染
- 375：CTA 693–741 → 616–664（视口 667，留 3px）；刊头 146→123；hero 标题 30→24。
- 390：CTA 702–750 → 625–673；主图 219h；白卡信息板 337→0（图下纸面）。
- 证据：[E2 前后对照](./round-4-compare-e2.png)；[375 基线](../../../prototype/round4/screenshots/baseline/hybrid-375-fold.png)；[375 改后](../../../prototype/round4/screenshots/after-e2/hybrid-375-fold.png)。

### 对比结论
**保留。** 375 首屏从「看不到完整 CTA」变为「完整看到 CTA」；主卡仍保留图片主导与衬线标题的编辑气质，但动作唯一、层级更短。

## 5. 实验 3 — 去掉没有承担发现任务的横滑轨

### 当前版本
主卡下方「本周出发」横滑区 272h，3 张卡片与主卡、列表前 3 项重复；卡片缺少距离 / 爬升，信息量低于列表；接缝筛选被推到首屏后 420px；a1 在主卡与横滑各出现一次。

### 改进方案
- 删除 `railCard()` / `cardSkeleton()` / `weekSection()` / `RAIL_N` / `railOf()` 及相关 CSS 段、`--hy-card-w` / `--hy-rail-gap` 变量。
- 主卡直接承接接缝带；接缝带与索引承担 upcoming 信息。
- footer 与 shell 标识更新为 Round 4；hybrid 说明改为「主卡 · 接缝筛选 · 密集比较」。

### 修改理由
横滑区没有提供主卡与列表之外的新信息，却占用 272px，并把真正的筛选 / 列表推迟约 414px。对只有 9 场活动的产品，这是「为机制而机制」；移除后页面路径更短、重复更少，发现任务由主卡与索引直接承担。

### 实际渲染
- 横滑区 272→0；列表起点 1264→850（相对基线）；a1 全页 2→1。
- 相对基线：`.page` scrollHeight 约 2184→1736（−448）；默认列表 8 条，全部重复计数为 1。
- 证据：[E3 前后对照](./round-4-compare-e3.png)；[E2 阶段全页](../../../prototype/round4/screenshots/after-e2/hybrid-390-full.png)；[E3 后全页](../../../prototype/round4/screenshots/after-e3/hybrid-390-full.png)。

### 对比结论
**保留删除。** 页面收敛为「主卡 → 接缝筛选 → 索引」一条连续路径；横滑轨的 JS / CSS / 变量一并清理，避免留下死代码。

## 8. 取舍与未解决问题

### 本轮明确保留的取舍

1. **筛选 / 搜索视图保留完整结果集**：默认视图去重 hero；「可报名」仍显示 a1（主卡 + 列表），因为筛选结果应完整。若下一轮希望所有视图一致，需要单独决定「hero 是否算筛选结果」。
2. **390 首屏接缝带底边 846 vs 视口 844**：仅裁到 tab 下沿 2px，不影响可读与操作；为保留当前节奏，未再做 2px 级压缩。
3. **错误态保留已加载内容**：沿用既有语义「保留重试入口，不清空已加载内容」；本轮未改动状态逻辑。
4. **其他页面不重做**：仅更新全局 shell 标识与 Round 4 简报路径；Editorial / Curated 作为对照，Detail / Collab / Weather 未改布局。

### 记录但本轮不解决（P2 / P3）

- 列表右列三行微字 + 4 种语义状态色，扫读时仍有噪点；需要状态色系统一或右列信息再分层。
- 缩略图 1:1 中心裁切（原图 720×450，`object-position: 50% 50%`）会切掉山脊主体；需要按图选择裁切焦点或改比例。
- 数字 / 单位格式不统一（`1,180 m` vs `km`）；需要统一的数字排版规则。
- a4 两行标题导致行高 98（其他行 81）；需要标题截断策略或允许两行的节奏规则。
