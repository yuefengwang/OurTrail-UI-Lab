# Round 3 设计简报 — 活动发现页三方案与设计语言精修

> 依据：Round 1/2 结论（`docs/ui-design/visual-direction-lab/`），A 山野编辑部与 F 山野工坊并列领先（88.0），C 静野 87.5 紧随。
> 本轮任务：在 A/F 的设计血脉上做**页面级深度设计**——活动发现页三套实质不同的版式方案 → 实测对照选优 → 提炼设计语言 → 迁移到活动详情/活动协作/天气 → 视口与交互验收。
> 纪律：不增加第八套全站风格；同一套演示数据（`prototype/js/data.js`）；不改生产仓库；截图数量不是验收标准。

---

## 1. 现状审计（发现页，基于实际截图与代码）

已核实的现状（`screenshots/` 与 `js/styles/{A,F,G}/index.js`）：

### A · 山野编辑部（当前并列领先）
- 刊头 + 头条整版封面 + 按月分组（每月 1 张大图条目 + 3 条紧凑行）。摄影驱动、层级清晰。
- 问题：① 第二张大图（青城后山）与头条争夺视觉重心，层级含糊；② 月份分组头（"10 月 4 项"）小字悬浮，节奏感弱；③ 紧凑行信息拥挤（缩略图 72px + 三行小字），每行事实结构不统一；④ 无"时间紧迫"表达，最近的出发没有存在感；⑤ 筛选行过于安静，"全部 9 / 可报名 5"与正文比例失衡。

### F · 山野工坊（并列领先）
- 工位面板（本月概览/检索与筛选）+ 编号台账行（01–08）+ 规格列（距离/爬升/名额/剩余）。
- 问题：① "工位 01 本月概览"占据首屏黄金位置——关于活动的统计先于活动本身出现；② 编号（01–08）与日期双轨，扫描时两套秩序互相干扰；③ 规格列在 375 上偏窄，数字与标签行高紧张；④ 头条仍是整版大图，首屏内"概览面板 + 大图"两个大块互相抢位。

### G · 橙白运动风（忠实镜像，未参评）
- 卡片墙：每场活动同尺寸卡片（图 + 元信息 + 事实 + 头像行）。无层级、扫描慢、卡片高，仅作对照基线。

### 共性缺口（三方案的改进靶点）
1. 出发时间与紧迫度没有被设计表达（最近一场与一个月后的一场，视觉同等）。
2. 图片来源与比例不统一（16:10 原图被自由裁切），图像规则未成体系。
3. 行/卡片的事实结构不统一：日期、难度、距离、爬升、名额的位置在各类条目间漂移。
4. 空气感与密度没有段落节奏——首屏之后一路同密度。
5. 空态/搜索无结果/过滤切换的反馈缺少设计。

## 2. 内容优先级与阅读顺序（设计依据）

用户打开发现页要回答的问题（按决策顺序）：

1. **现在能报什么名？最近什么时候出发？**（时间 + 可报名状态）
2. **这条线什么水平？多远、多少爬升、去哪？**（路线画像）
3. **谁带队？多少人？还剩多少名额？**（信任 + 稀缺）
4. **状态是什么？**（报名中 / 名额紧张 / 已成行 / 已结束 / 已取消 —— 词表来自演示数据）
5. **下一步做什么？**（看详情 → 报名；本轮原型中为可点按跳转 + 反馈）

单条目扫描顺序（三方案共用原则）：**日期/时刻 → 标题 → 路线与难度 → 事实（距离·爬升·领队·名额） → 状态**。
页面级阅读顺序：**期刊/身份感 → 检索工具 → 视觉引导（1–3 个重点） → 完整索引 → 下一步**。
三方案对"视觉引导"的答案不同：编辑特写=封面故事；策展索引=下一场出发；混合发现=近期出发横滑。

## 3. 共同设计基线（三方案共享，冻结）

### 3.1 色板（出自 A/F 血脉，语义角色固定）

| 角色 | 值 | 用途纪律 |
|---|---|---|
| 纸面 `--r3-bg` | #F7F4EC | 页面底 |
| 石色 `--r3-surface-2` | #EFEBDD | 分组底/信息带 |
| 正文 `--r3-ink` | #1B241F | 标题与正文 |
| 次要 `--r3-ink-2` | #66705F | 元信息 |
| 弱 `--r3-ink-3` | #8A917F | 脚注/水印 |
| 发丝线 `--r3-line` | #E4DDCB | 所有分隔 |
| 品牌绿 `--r3-brand` | #234B3C | 品牌动作 / 主按钮 / 压底 |
| 陶土 `--r3-accent` | #A8562E | **仅**时间紧迫/名额紧张（如"剩 3 位""名额紧张"）|
| 语义色 | success #2F6B4C · warning #8F6A1F · danger #A93F33 · info #46657A | 状态词、四态 |

### 3.2 字体
- UI/正文：系统无衬线栈（-apple-system, PingFang SC）。
- 编辑性标题（页面大标题、活动标题、数字大写）：衬线栈（Georgia, Songti SC, Noto Serif SC, SimSun）——延续 A/F 的"刊物感"，本轮收敛为**统一用法**：衬线只出现在"被当作叙述主体的文字"上，事实与元信息一律无衬线。
- 数字：tabular-nums；字号差建立层级，不靠颜色。

### 3.3 尺度
- 字号：display 30 / title 26 / section 16–17 / lede·body 15 / caption 12 / micro 11（+字距 1.4 的 kicker 11）。
- 间距：4px 基元；页边距 24（375 视口 20）；区块间距 32–40（各方案自定节奏）。
- 圆角：图片 2 / 按钮 6 / 徽标 pill；内容面不出现卡片阴影，仅 1px 发丝线。
- 触控：操作热区 ≥44；主按钮高 48。

### 3.4 图像规则（三方案共同遵守）
- 素材为 9 张 720×450（16:10）氛围图；`cover` 字段决定用图，`credit` 脚注必须保留。
- 裁切比例按角色固定：封面 16:10 / 组件 4:3 / 行内缩略 1:1。同一角色在三方案内比例必须一致。
- 图上压字必须带压暗梯（scrim），白字对比 ≥ AA。

### 3.5 共享组件（base.css 提供形态，三方案自有排版）
kicker · 事实行 · 状态词（点+词，语义色）· 名额文案（`剩 N 位`/`满员`）· 按钮（主/文字链）· 搜索框 · 月份分组头 · 脚注 · 空/错/加载状态块 · toast。

## 4. 三套版式方案规格

> 三案必须共享 §3 基线，但**页面构图与信息组织必须实质不同**。以下为规格与验收锚点。

### 方案一 · Editorial Feature（编辑特写）「本期」
**概念**：发现页 = 一期周刊。封面故事占据首屏主位，其余内容以"编辑推荐 + 出发日历"展开。层级靠**叙述权重**（封面 ＞ 推荐 ＞ 日历）。

**结构（自上而下）**
1. 刊头：kicker「发现 · 第 04 期」+ 右侧日期「10 月 17 日」；display 衬线「发现」；导语一行。
2. 工具行：搜索下划线输入 + 状态文字页签（全部 9 / 可报名 5 / 已成行 2 / 已结束 2），编辑评注式排版（小字 + 计数）。
3. **封面故事**（本期头条 = a1 赵公山）：16:10 通栏大图 + 底部压暗梯（图上：`明晚 22:10 出发 · 10 月 18 日 周六`）；图下：kicker「本期头条 · 都江堰 · 进阶」→ 衬线 26 标题 → 路线名 → 导语（15，两行）→ 事实行（18.6 km · ↑1,180 m · 名额 24 · 剩 7 位）→ 动作行（文字链「查看安排 →」+ 状态「报名中」）。
4. **编辑推荐**（2 条 = a2 青城后山、a4 四姑娘山）：横向条目——4:3 图（约 40% 宽）+ 右侧：标题（衬线 17）、编辑按一行（13，引自数据事实）、事实微行。
5. **出发日历**（其余活动，按月分组）：日期轴（大号日数字 + 星期）+ 标题 + 路线/难度 + 事实行 + 右列状态/名额；**纯文字行，无缩略图**（与上部的摄影区形成"图—文"节奏对比）。分组头：「10 月 · 4 场  10/11–10/26」。
6. 脚注（演示数据 + Unsplash 声明）。

**交互**：页签与搜索作用于全页——默认"全部"显示完整编辑结构；选择状态/输入搜索后切换为"列表模式"（隐藏封面与推荐，日历显示匹配结果）。空结果显示状态块 + 清除动作。

**首屏目标（390）**：刊头 + 工具行 + 封面大图完整可见；封面标题在首屏下缘出现。

### 方案二 · Curated Activity Index（策展索引）「索引」
**概念**：发现页 = 一座可扫描的活动索引。没有封面故事；**日期是索引的第一主轴**，每行结构完全一致；图像降级为"证据缩略"，只保留一处功能性重点（下一场出发）。

**结构（自上而下）**
1. 索引头：kicker「发现 · 活动索引」+ 日期；衬线标题「发现」；一行统计导语「成都周边 · 9 场 · 按出发时间排序」。
2. 检索区：**强分段控制**（全部 9 / 可报名 5 / 已成行 2 / 已结束 2，下划线式，选中加重）+ 搜索框（框式，40px，带搜索图标）。
3. **下一场出发**（a1）：石色信息带——左：日期块（10 月 18 日 / 周六 / 22:10）；中：标题 + 路线；右：4:3 缩略（96×72）；下行：事实行 + 状态 + 「距出发 1 天」；整块可点按，右侧箭头。
4. **月度索引**：分组头「10 月 · 4 场」；每行统一栅格：［日期 44px：10/25 + 周六］［缩略 56×56］［主区：标题 15/600 + 路线 12 + 事实行 12］［右列 64px：状态词（语义色）+ 名额（tabular，陶土=紧张）］；行高 76，发丝线分隔。11 月同构。
5. 脚注统计「共 9 场 · 演示数据」。

**交互**：分段控制 + 搜索实时过滤；过滤后分组头与计数联动；空结果状态块。

**首屏目标（390）**：索引头 + 检索区 + 下一场出发带 + 「10 月」分组头 + 2–3 行完整可见。密度优先。

### 方案三 · Hybrid Discovery（混合发现）「先看，再挑」
**概念**：页面分两段节奏——上半"发现区"（allure：1 张主卡 + 3 张横滑卡），下半"比较区"（索引式密集列表）。两段之间有一次明确的设计接缝（石色带）。“横向滑动”是实验室从未出现过的机制。

**结构（自上而下）**
1. 刊头：kicker + 衬线标题「发现」+ 右侧日期；一句导语（可选）。
2. **主卡（Hero Card）**：16:9 图 + **负外边距信息板**（白底、发丝线，向上叠压图片 24px）：kicker「最近出发」→ 衬线 20 标题 → 路线 → 事实行 → 动作行（主按钮「查看安排」+ 状态）。信息板与图叠压是本方案的签名机制。
3. **本周出发 · 横滑轨**：「本周出发」小标题 + 「向左滑」提示；3 张 160px 宽 scroll-snap 卡（4:3 图 + 日期 + 标题两行 + 名额/状态微行）；滑轨右侧露出下一张的边（滑动暗示）。
4. **接缝带**：石色通栏，内容「全部活动 · 按出发时间」+ 状态页签 + 搜索；向下滚动时 sticky 吸顶（页面内滚动容器内 position:sticky）。
5. **比较列表**：与索引相似的栅格行（日期轴 + 64px 缩略 + 主区 + 右列状态/名额），行高 80，按月分组。
6. 脚注。

**交互**：横滑轨真实可滑（scroll-snap）；接缝带页签/搜索过滤列表；主卡与行可点按跳详情。

**首屏目标（390）**：刊头 + 主卡图片上半 + 信息板起始可见；滑轨在第二屏。

## 6. 纪律边界
- 不新增第八套全站风格；三方案的差异是**页面级构图**，不是新风格体系。
- 不删减任何业务信息（9 场活动、全部状态词、全部事实字段）。
- 不虚构后端能力；"距出发 1 天/明晚"等仅为演示时间推导文案，写入交付说明。
- 不覆盖其他 Agent 工作；所有改动限于 `prototype/round3/` 与 `docs/ui-design/round-3/`。
- 每项主要修改可回答四问：原问题 / 为何影响用户 / 新机制 / 渲染证据。
