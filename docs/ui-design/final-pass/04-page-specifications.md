## 0. 全站页面契约

### 0.1 导航

```
发现 ──查看安排──> 详情 ──路线天气──> 天气
  ^                 |  ^                |
  |                 |  └──返回──────────┘
  └──返回───────────┘
                    |
                    └──组织者/协作/车长──> 协作 ──返回──> 详情
```

- 发现 → 详情：`go('detail', {activityId})`。

- 协作返回：回详情组织者视角；天气返回：回详情，保留当前报名状态。

## 1. 发现页（Discover）

### 1.1 页面任务与决策顺序

任务：让用户快速找到“还没出发、值得参加”的活动，并进入详情。

决策顺序：
1. 最近哪一场？（日期/时间/集合）
2. 是什么活动？（标题/路线/城市/图）
3. 适不适合我？（距离/爬升/难度）
4. 值不值得去？（费用/领队/一句话）
5. 还能不能报？（状态/余位/截止）
6. 下一步？（查看安排）

### 1.2 页面顺序

1. **顶栏**（非 sticky）：成都周边、发现、日期、头像。
2. **主推卡**：通栏 16:9（375 为 2.05:1）+ 图上时间/倒计时 + 图下状态行、标题、路线、四格事实、领队/人数/待审核/天气一句、唯一 CTA。
3. **筛选条**（sticky）：搜索钮 + 4 个页签；点击搜索展开输入。
4. **接下来**：按月分组的索引行；默认排除主推。
5. **已结束与已取消**：默认折叠，展开后显示过去行。
6. **脚注**：演示数据/图片来源。

### 1.3 主推卡规格

| 元素 | 内容 | 数据 |
|---|---|---|
| 图 | 青城后山石阶林径（AI 氛围图，非实拍） | `cover` + `focus` |
| 图上标签 | 最近出发 | 位置 |
| 图上时间 | 明天 07:00 集合 · 茶店子 | `meetingPoints[0]` |
| 图上倒计时 | 距集合 10 小时 | `meetingAt - NOW` |
| 状态行 | 名额紧张 · 余位 3/24 · 今晚 21:00 截止 | `statusKey/remaining/deadlineAt` |
| 标题 | 青城后山 · 飞泉沟轻徒步 | `title` |
| 路线 | 泰安古镇 · 飞泉沟 · 白云索道下站 · 都江堰 | `routeName/city` |
| 事实 | 12.8 km / 680 m / 入门 / ¥168 | `distanceKm/ascentM/difficulty/fee` |
| meta | 领队 陈屿 · 18 人已确认 · 3 人待审核 · 活动日午后有阵雨 | `leader/confirmed/pending/weather` |
| CTA | 查看安排 → | 唯一主按钮 |
| 交互 | 图片/标题/CTA 均进详情；整卡不是 button | — |

### 1.4 索引行规格

- 日期列：`25`（18px）+ `周日`（9.5px）；月份由分组头提供。
- 缩略：58×43.5（4:3），`object-position: focus`；过去行 saturate .55。
- 主列：标题 13.5px（单行省略；括号内容拆标签）；路线 10px；事实 10px（距离/爬升/难度/费用）。
- 右列：状态词（形状+文字）+ 余位（≤3 陶土）。
- 行高 72px；整行是 button；aria-label 包含标题/日期/状态/余位。
- 默认视图不含主推；筛选/搜索包含主推并标 `主推`。
- 过去组：2 行，默认 `<details>` 折叠；筛选“已结束”自动展开。

### 1.5 筛选/搜索

- 页签：全部 9 / 可报名 5 / 已成行 2 / 已结束 2。
- 搜索：活动名、路线、城市、领队、难度；命中 1 条（牛背山），无结果给空态 + 清除。
- 默认列表排除主推；搜索/筛选返回完整结果。
- 空态/错误/加载：
  - 空态：没有匹配的活动 → 清除筛选。
  - 错误：活动加载失败 → 重新加载；不展示过期数据。
  - 加载：主推 + 行骨架；不制造布局跳动。

### 1.6 验收

- 375：主 CTA 底 ≤603（实测 471）；首行起点 587（页面内可见 16px）。
- 390/414：主 CTA + 首行完整可见；无横向溢出。
- 搜索/筛选/过去折叠均可用；0 console error。

## 2. 详情页（Detail）

### 2.1 页面任务与决策顺序

任务：让用户判断“值不值得去、适不适合我、怎么去、现在做什么”。

顺序：
1. 我的报名状态与下一步。
2. 活动身份（图/名/路线/时间/城市）。
3. 快速决策事实（距离/爬升/难度/费用/名额/截止）。
4. 适合谁 + 风险摘要。
5. 路线与集合（地图/剖面/节点/上车点/天气入口）。
6. 行程安排。
7. 出发前准备（装备 + 风险）。
8. 发起人与我的安排。
9. 费用与退出。
10. 底部唯一主行动。

### 2.2 页面顺序与组件

1. **App Bar**：返回、活动详情、活动名、分享、更多。
2. **Hero**：通栏 16:9 图（图下纸面，不叠白卡）；图上日期/集合 + 距集合 pill；图下状态行、H1、路线、四格事实、适合谁。
3. **状态条**：按报名/角色状态变化（见 2.3）。
4. **适合谁 / 需要留意**：两列；不套卡片。
5. **路线与集合**（`#route`）：
   - SVG 路线示意（等高线、方向、1/2/3、指北、`路线示意 · 非导航地图`）。
   - 海拔剖面（800/1000/1200m；三点；点选联动）。
   - 3 个节点行（名称/备注/海拔/ETA）；点选地图与剖面。
   - 车站点：07:00 茶店子/07:20 犀浦；已确认/待审核标“我的上车点”。
   - 天气入口：活动日午后阵雨 + 12:00–16:00 58–82% + 建议 12:30 前通过；点击进天气。
6. **行程安排**：集合与去程 / 上山 / 下撤与返程；时间 + 文案；12:40 标“折返判断”。
7. **出发前准备**：6 项装备可勾选 + 进度；风险 2 条（雨后石阶湿滑/山脊风大）。
8. **发起人与同行**：头像、姓名、发起人·领队、介绍、18 人已确认/协作许安；已确认显示“我的安排”（上车点/车辆座位/签到）；组织者显示待审核/未分车/完整名单仅在协作页。
9. **费用与退出**：人均 ¥168、群内结算、退出约定、平台不收款。
10. **底部行动条**：说明 + 唯一主 CTA + 至多一个次操作。

### 2.3 状态矩阵

| 状态 | 状态条 | 主 CTA | 次操作 | 不允许 |
|---|---|---|---|---|
| new | 报名今晚 21:00 截止；余位 3/24 · 18 已确认 · 3 待审核 | 填写报名资料 | 分享 | 超截止报名 |
| pending | 报名已收到；待审核 4 · 余位 2 / 24（会话提交后） | 查看我的报名 | 取消报名 | 自行通过 |
| confirmed | 名额已确认；1 号中巴 · 03 座 · 茶店子 07:00 | 查看集合与出行安排 | 路线天气 | 改分车 |
| waitlist | 候补第 2 位；不占正式名额 | 查看我的报名 | 退出候补 | 直接 confirmed |
| withdrawn | 你已取消本次报名；名额已释放 | 重新报名 | 分享 | 出发后取消 |
| closed | 报名已关闭；安排仍可查看 | 看看其他活动 | 分享 | 报名 |
| cancelled | 活动已取消；不再执行行程 | 看看其他活动 | 分享 | 现场操作 |
| archived | 活动已归档；仅供回看 | 看看其他活动 | 分享 | 任何写操作 |
| organizer | 你发起的活动 · 行前准备；3 待审核 · 1 未分车 | 进入协作工作台 | 参与者视角 | 以参与者身份报名 |

### 2.4 报名 sheet

- 标题：填写报名资料；副标题：活动 + 截止时间。
- 字段：姓名、手机号、紧急联系人、紧急联系人手机、出行方式（搭乘/自行）、上车点、数据使用同意（必填）、同行代办授权（选填）。
- 校验：姓名 ≥2 字；手机 11 位且 1 开头；紧急联系人姓名/手机必填；搭乘必须选上车点；同意必须勾选。
- 提交：按钮 loading 480ms → 关闭 → 写入本地事务名单（沈岚 pending）→ 详情待审核 4 / 余位 2 → toast「报名已提交（本地事务）」。
- 说明：提交后领队审核；待审核占名额；候补不占正式名额；敏感资料不展示给其他参与者。
- **事务**：审核通过后详情变 confirmed（19 已确认），取消后释放名额；发现/详情/协作计数同步。
- **边界**：状态在内存中，刷新重置；不是后端，正式实现必须映射真实命令（见 05/07）。

### 2.5 角色与隐私

- 参与者：只看到领队/协作、自己的安排；不显示全量名单、电话、他人座位/签到。
- 组织者：可进协作工作台；详情只显示待审核/未分车计数。
- 敏感资料：详情不展示；协作也不在名单展示，需按用途另行查看。
- 分享：复制活动名 + 日期 + 集合 + URL；失败给 fallback 文案。

### 2.6 验收

- 375/390/414 底部主 CTA 始终可见；首屏有状态、事实、适合谁。
- 8 个状态 + 组织者均可渲染；关闭/取消/归档无假按钮。
- 路线点与天气页同名同序；地图标注“非导航”。
- 0 console error；无横向溢出。

## 3. 协作页（Collab / Workspace）

### 3.1 页面任务与决策顺序

任务：组织者/协作/车长清除阻塞、推进阶段、完成现场任务。

顺序：
1. 现在什么阶段？离下一阶段还差什么？
2. 最紧迫的未完成事项是什么？谁来做？
3. 有没有异常/冲突？
4. 名单/车辆/现场明细（按任务进入）。
5. 下一步唯一操作；完成后的反馈。
6. 阶段推进后优先级如何变化。

### 3.2 页面顺序

1. **App Bar**：返回、活动协作、活动名、查看详情。
2. **指挥带**（深松绿）：角色、阶段、活动名、日期/集合/时间锚点、5 段步进、3 个关键统计。
3. **现在要做**：任务队列（审核/分车/签到/异常/到家/截止/只读）；无任务时给“可以推进/已归档”。
4. **页签**（仅组织者）：名单 / 车辆 / 现场 + 计数；sticky 在 App Bar 下。
5. **名单**：搜索 + 筛选 + 需要处理/已就绪/已处理分组 + 行内动作。
6. **车辆**：未分配区 + 车辆块 + 可展开座位图 + 车长视角入口。
7. **现场**：阶段统计 + 阶段检查 + 待处理名单 + 阶段推进按钮。
8. **脚注**：演示数据/名单边界。

### 3.3 指挥带

| 元素 | 内容 |
|---|---|
| 角色 | 组织者视角 / 现场协作 · 许安 / 1 号中巴车长 · 许川 |
| 阶段 | 行前准备 / 正在集合 / 正在同行 / 返程报平安 / 已归档 |
| 活动 | 青城后山 · 飞泉沟轻徒步 |
| 时间锚点 | 今晚 21:00 报名截止 / 明早 07:00 茶店子集合 / 预计 12:40 白云索道下站 / 返程原因 |
| 步进 | 行前 → 集合 → 同行 → 返程 → 归档（当前叶色） |
| 统计 | 组织者：18/24 已确认 · 3 待审核 · 1 未分车；集合：已签到/未签到/未分车；同行：已出发/到飞泉沟/异常；返程：已到家/未确认/异常；车长：本车乘客/已上车/空余 |

### 3.4 任务队列

| 任务 | 条件 | 动作 | 完成反馈 |
|---|---|---|---|
| 审核报名 3 | published 且 pending>0 | 去审核 → 名单 | 通过/拒绝后 pending 减少；0 时任务消失 |
| 安排车辆 1 | published/gathering 且 confirmed 拼车未分车 | 去分车 → 车辆 | 安排后未分车减少；任务计数更新 |
| 报名今晚截止 | published | 查看名单 | 只读时间锚点 |
| 未签到人员 N | gathering | 去签到 → 现场 | 签到后未签到减少 |
| 未安排车辆 N | gathering | 去分车 → 车辆 | 同上 |
| 待处理异常 | active/closing | 去处理 → sheet | 解决后任务消失；未解决阻断归档 |
| 待到家人数 N | closing | 去确认 → 现场 | 逐人到家后减少 |
| 活动已归档 | archived | 查看记录 | 只读 |

- 任务按阻塞程度排序；计数来自同一 `scenario` 派生。
- 任务完成即时更新页面（rerender + toast），不靠“假成功”。

### 3.5 名单

- 搜索：姓名/车辆/上车点；筛选：全部/需要处理/待审核/已确认（协作视角：全部/未签到/已签到）。
- 分组：需要处理（clay）→ 已就绪 → 已处理（未通过）。
- 行：头像、姓名+角色、上车点+车辆/座位、状态形状；主区点开成员状态；侧动作只给当前任务。
- 审核 sheet：申请时间、上车点、出行方式、名额占用；通过/拒绝。
- 分车 sheet：覆盖上车点的车辆 + 空位；司机不占乘客座；同行组不静默拆开（生产）。
- 签到：直接执行 + toast；不弹确认（高频）；状态行立即变为已签到。
- 到家：必须填写依据 + 勾选“已获得授权”；不能批量代签。
- 异常：四类中本轮展示迟到；处理结果必填；解决后才能推进/归档。
- 不展示电话/健康/紧急联系人。

### 3.6 车辆

- 统计：车辆数/已确认/车上乘客/司机/自行前往/未分配。
- 车辆块：车号/车牌/司机/已分配/乘客位/进度条；展开座位图。
- 座位：真实编号 01–18 / 01–06；空位虚线；司机不在乘客座。
- 未分配：姓名 + 上车点 + 安排。
- 只向有乘客的车辆推送/发车（生产）。
- 车长视角：本车 10 名乘客；逐人确认上车；未签到不能上车；发车前点清缺口；完成本程 ≠ 到家。

### 3.7 现场与阶段门槛

| 推进 | 门槛 | 本轮行为 |
|---|---|---|
| 行前 → 集合 | pending=0 | 未清零则按钮禁用“仍有 N 项未完成”；分车缺口只提醒，不阻断集合 |
| 集合 → 同行 | 未签到=0；未分车=0；异常=0；车长确认 | 弹层勾选“已与车长确认”；缺一项禁用 |
| 同行 → 返程 | 异常=0；填写原因 | 原因必填；异常未解决禁用 |
| 返程 → 归档 | 未到家=0；异常=0 | 逐人到家 + 依据；禁用按钮点名缺口 |

- 推进后不可回退；页面重绘阶段、统计、任务和面板。
- 实验控制的下拉可直达阶段，仅用于验收；产品内只走门槛弹层。

### 3.8 角色

| 角色 | 可见 | 不可见/不可做 |
|---|---|---|
| 组织者 | 任务、全量名单、车辆、现场、审核/分车/推进/导出（生产） | —（保留真实权限边界） |
| 现场协作 | 签到、节点、异常；已确认成员 | 审核报名、分车、阶段推进、代确认到家 |
| 车长 | 本车 10 名乘客、两程上车/发车 | 全量名单、敏感资料、异常、分车 |

### 3.9 验收

- 首屏任务队列（375/390/414），不是 4×4 网格；首条任务 329–389。
- 审核 3→0、分车、签到、异常、到家、阶段推进均可执行并更新。
- 车长/协作视角无越权组件。
- 无横向溢出；0 console error。

## 4. 天气页（Weather）

### 4.1 页面任务与决策顺序

任务：判断路线关键点在活动时间内的天气风险，形成“更值得关注/怎么安排”的判断。

顺序：
1. 哪场活动、哪个点、哪个时间范围？
2. 活动窗口内最值得关注的时段？
3. 降水/风/温度/云底如何影响这段路线？
4. 哪个海拔点更值得关注？在云中/云上？
5. 数据范围、更新时间、模拟/预报限制？
6. 对安排的建议？
7. 返回详情。

### 4.2 页面顺序

1. App Bar：返回详情、活动天气、路线天气、活动详情。
2. 身份带：活动名、活动日、集合、路线、距离/爬升、模拟徽标、判断摘要、置信、范围、生成时间。

## 5. 跨页连续性

### 5.1 事实

见 02 第 7 节；所有值来自 `data.js`，页面不硬编码活动事实。

### 5.2 任务链

- 发现 → 详情：活动身份不丢；返回恢复筛选/搜索/滚动。
- 详情 → 报名：提交后 pending；主 CTA 变“查看我的报名”。
- 详情 → 天气：活动/点/时段上下文保留；返回详情。
- 详情 → 协作：组织者/协作/车长；返回详情组织者视角。
- 协作 → 参与者视角：详情 new；不把组织者数据带到参与者视图。
- 天气 → 详情：返回活动，不丢当前报名状态。

### 5.3 一致性规则

- 同一活动名称/路线/时间/距离/爬升/费用/领队/名额/路线点/天气窗口在所有页面同源。
- pending 占名额；候补不占正式名额；remaining = capacity − confirmed − pending。
- 签到 ≠ 上车；发车完成 ≠ 到家；候补 ≠ 正式名额。
- 参与者详情不出现全量名单/敏感资料；车长只本车。
- 报名/审核/取消后，发现/详情/协作三页计数同步（S12–S24）；发现页主推在会话中显示 19 已确认 / 3 待审核 / 余位 2，取消后回到 18 / 3 / 3。
