# 03 · OurTrail Final Pass 设计系统

> 适用范围：发现、详情、协作、路线天气四页；也是迁移到正式微信小程序的 token/组件契约。
> 实现：`prototype/final/css/tokens.css`、`base.css`、`app.css` + 页面 CSS；无外部 UI 框架。
> 原则：纸面感不等于杂志排版；品牌感不等于装饰；每个容器必须有业务理由。

---

## 1. 设计原则（按产品任务排序）

1. **先回答“我现在能做什么”，再展示“这场活动有多美”。**
2. **同一事实只在一个主位置说一次；其他页面引用同一数据源。**
3. **状态先于颜色**：词 + 形状 + 位置；颜色只做强调。
4. **图片是活动识别，不是遮住信息的背景。**
5. **容器是关系，不是装饰**：正文、名单行、时间轴不需要卡片；弹层、车辆、座位、表单才需要容器。
6. **数据图必须能完成任务**：有单位、有范围、有选中、有空态、有数据来源与限制。
7. **页面因任务不同而不同**：发现偏索引，详情偏决策，协作偏执行，天气偏判断；共享 token，不共享模板。

## 3. 字体与排版

### 3.1 字体栈

```css
--sans: -apple-system, "PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif;
--serif: "Songti SC", "Noto Serif SC", "Source Han Serif SC", "STSong", "SimSun", Georgia, serif;
```

- **衬线只给叙述主体**：主推活动标题、详情活动标题、协作活动标题。页面标题、区块标题、数据、按钮、表单全部无衬线。
- **数字一律 tabular**：价格、距离、爬升、时间、余位、海拔、降水、风。
- 中文单位与数值之间留 2–4px；单位弱化（10.5–11px，ink-3），数值强调。
- 不用英文眉题制造高级感；所有 kicker 为中文短句（“最近出发”“活动日参考”“现在要做”）。

### 3.2 字号/字重/行高

| 角色 | 字号 | 字重 | 行高 | 用途 |
|---|---:|---:|---:|---|
| 主推/详情活动标题 | 21–26px | 700 | 1.22–1.24 | 青城后山 · 飞泉沟轻徒步 |
| 页面标题 | 22px | 750 | 1.15 | 发现 |
| 区块标题 | 15–16px | 650–700 | 1.35–1.4 | 路线与集合 / 现在要做 |
| 协作指挥带标题 | 21px | 700 | 1.24 | 活动名（暗底） |
| 正文 | 15px | 400 | 1.5–1.55 | 说明、风险建议 |
| 小正文 | 13px | 400–600 | 1.45–1.5 | 名单姓名、任务标题 |
| 辅助/数据 | 10.5–12px | 400–650 | 1.3–1.5 | 路线、事实、单位、时间 |
| 微字 | 8.5–10px | 600–700 | 1.2–1.4 | 标签、图表刻度、表头 |
| 数值强调 | 15–21px | 700 | 1.1–1.2 | 距离/爬升/人数/统计 |

约束：
- 不在同一屏使用 3 个以上衬线尺度；本系统只用 2 个（21–26 标题 / 无其他）。
- 列表标题不超过 1 行；长标题拆“2 日”等标签，不把括号内容挤成省略号。
- 正文不用纯黑；用 ink / ink-2；弱化信息用 ink-3。

## 4. 间距、栅格与布局

- 基元：4px。
- 页边距：390 → 20px；375 → 18px；414 → 22px。
- 区块节奏：28px；紧凑区块 16–20px；名单行 9px 上下；任务行 11px 上下。
- 事实栅格：4 等分；格间 1px 发丝线；标签 9.5px、值 15px。
- 发现索引：日期 30px / 缩略 58px / 主列 1fr / 右列 auto / 箭头 12px；行高 72px。
- 详情路线点：24px 序号 / 主列 1fr / 右侧海拔与 ETA；行高 44px。
- 协作名单：32px 头像 / 1fr / 侧动作；行高约 56–64px。
- 天气点：3 等分；图表全宽；对比表 5 列（1.45fr / .62fr ×3 / .9fr）。
- 底部行动条：48px 主按钮 + 10px 上边距 + 12px 下边距；页面内容底部留出安全区。
- 不使用大圆角；图片 4px，按钮 8px，标签 3–4px，胶囊 999px。
- 不用阴影做层级；阴影只给弹层。区块靠留白、发丝线、字重和底色区分。

### 何时用容器

| 内容 | 容器 |
|---|---|
| 活动正文、路线、行程、装备、费用 | 不套卡片；纸面 + 发丝线 |
| 状态/提醒 | 左侧 3px 竖线 + 渐变底（state-strip） |
| 任务/名单 | 行，不套卡片 |
| 车辆/座位 | 车辆块 + 可展开座位图（真实容量） |
| 图表 | 无卡片；图例 + 刻度 + 数据说明 |
| 表单/弹层 | sheet + surface 底 |
| 空态/错误 | 空态块 + 单一出口 |

## 5. 组件规格

### 5.1 App Bar
- 高度 50；纸面底；sticky；滚动后下边线出现。
- 左：38px 返回圆钮（chevron 旋转 180°），或发现页品牌位。
- 中：9.5px 中文 eyebrow + 14px 标题；标题单行省略。
- 右：38px 图标钮（分享/更多/活动详情），必须有 aria-label。
- 详情页标题可与 H1 重复；天气/协作的 nav 标题使用任务名（路线天气/活动协作），避免与 H1 完全重复。

### 5.2 主按钮/次按钮
- 主：48px 高，brand 底，on-dark 字，8px 圆角；一屏只有一个主按钮。
- 次：透明底 + 1px brand 边；ghost：仅文字；danger：1px danger 边 + 透明底。
- 小操作：30–34px 高；主操作 48px；appbar 图标 40px；sheet 关闭 36px；地图点命中区 32px。生产建议次级操作放大到 40–44px 或扩大热区；不得只靠图标表达关键动作。
- 禁用：opacity .42 + cursor not-allowed；禁用按钮必须说明原因（阶段未到/仍有缺口），不做“看起来能点”的假按钮。

### 5.3 状态词
- 结构：形状（dot / check / minus / x）+ 文字 + 颜色。
- 活动：可报名 / 名额紧张 / 已成行 / 已结束 / 已取消。
- 报名：待审核 / 已确认 / 候补中 / 已取消报名 / 报名关闭 / 已归档。
- 成员：待审核 / 已确认 / 未通过 / 未签到 / 已签到 / 未分车 / 协调中 / 未到家 / 已到家。
- 阶段：行前准备 / 正在集合 / 正在同行 / 返程报平安 / 已归档。
- 颜色语义：brand=确认/完成；clay=需要处理/紧迫；danger=异常/取消；ink-3=只读/过去。
- 不用“已通过/已满/已截止”作为报名记录状态；已满/截止是派生展示。

### 5.4 事实条
- 4 格；标签 9.5px，值 15px，单位 9.5px。
- 发现主推：距离 / 爬升 / 难度 / 人均；详情：距离 / 爬升 / 难度 / 人均。
- 名额：`余位 N / capacity`；pending 占名额；候补不占正式名额。
- 时间：发现用“明天 07:00 集合”，详情用“10/24 周六 · 07:00 茶店子客运站”。

### 5.5 状态条（state-strip）
- 左侧 3px 竖线（brand/clay/danger/mute）+ 17px 图标 + 13px 标题 + 11.5px 正文 + 10.5px meta。
- 用于详情报名状态、协作阶段提示、天气模拟声明。
- 不做成卡片；不重复底部行动条的同一句话。

### 5.6 底部行动条
- sticky bottom；纸面 .97 底；上发丝线；上边 10px、下边 12px + safe-area。
- 左侧 10.5px 说明（余位/截止/集合），右侧 10.5px 状态尾巴（领队审核/已确认/组织者/只读）。
- 一个主按钮 + 至多一个 ghost/icon 次操作；主按钮始终唯一。
- 页面底部内容必须能在行动条之前完整滚动；full 截图验证。

### 5.7 弹层 / 表单
- sheet 从底部进入；18px 上圆角；surface 底；scrim 48% 深色；最大高度 88%。
- 标题 17px + 12px 说明；关闭 32px；Esc/点背景关闭。
- 表单：40px 输入；11px 标签 + 8.5px 必填；10.5px 错误；首个错误字段 focus。
- 报名字段：姓名、手机号、紧急联系人、紧急联系人手机、出行方式、上车点、数据使用同意、同行代办授权（选填）。
- 审核/分车/到家/异常/阶段推进均使用 sheet；关键规则写在 sheet 内（名额占用、代确认授权、门槛）。

### 5.8 任务行
- 左侧 3px 色条（clay 阻塞 / warn 风险 / brand 普通 / danger 异常）。
- 标题 13px；计数 18px 胶囊；meta 10px；“去审核/去分车/去签到/去处理”11px 链接。
- 任务按阻塞程度排序；任务完成后立即从队列消失，底部 toast 反馈。
- 不做“组件优先级”排序：名单/车辆/现场都在任务之后。

### 5.9 名单行
- 32px 头像 / 姓名+角色 / 上车点+车辆座位 / 状态形状 / 侧动作。
- 主区是按钮（可打开成员状态）；侧动作只保留当前要做的任务；已就绪行不再重复“查看”。
- 需要处理分组在前；搜索 + 筛选；不展示电话/健康/紧急联系人。
- 车长视角只显示本车乘客；协作视角只显示已确认成员。

### 5.10 车辆与座位
- 车辆块：车号/车牌/司机/乘客位/已分配/进度条；不把司机算乘客。
- 座位图：仅在展开时显示；按真实座位号（01–18 / 01–06），6 列；空位虚线。
- 未分配区：姓名 + 上车点 + “安排”；安排 sheet 先选车再选空位；覆盖上车点校验。
- 同行组/预留位/司机换人属于生产规则，不在演示中伪造。

### 5.11 路线图与海拔剖面
- 路线图 327×184：坐标来自 `routeSnapshot.points`；等高线是地形暗示；路线 3.2px 深绿 + 白描边；方向箭头；起点实心、途中白底描边、终点深绿；点选高亮 13px 虚线环；指北针；`路线示意 · 非导航地图` 常驻。
- 海拔剖面 327×94：800/1000/1200m 虚线；面积 #DCE3D3；线 2px brand；三点；点名 7.5px；点选联动地图。
- 无坐标/无 track：不画假地图；显示“路线节点由组织者补充”。

### 5.12 天气图
- 327×286，四层：
  1. 云底 600–2400m（虚线 + 上方云层淡填充）+ 选中点海拔虚线（陶土）+ 在云中判断。
  2. 降水概率 0–100%（2h 聚合柱；≥60% 加深）。
  3. 气温（动态 min/max；1.7px 线）。
  4. 风（每 6h 箭头 + 数值）。
- 活动窗口 10/24 07:00–18:00 绿色括号/tint；关键时段 tint + 顶部标签；选中小时竖线 + 两个圆点 + 底部时间标签。
- x 轴每 6h 标签（日期 + 时间）；不挤 48 个标签；图例完整；单位 °C / % / mm / m/s / m / km。
- 点击图选最近整点；切点/切范围/点关键时段均联动。
- 数据不足：不插值；显示范围与回退。
- **375 compact**：viewBox 高 246；三车道（云底/降水/气温）；字号 8.8/8；不画风箭头，风由选中详情/路线对比承载；图例显示“风见选中详情”。375 同时收起 hero 距离/爬升与 summary 说明第二行，保留模拟徽标、范围、限制与数据说明。实测图表 272–601，完整进入 603 首屏。
- 生产：canvas 2×/3× DPR 绘制；颜色与刻度从 token/数据派生；不用截图式假图。

## 7. 文案规则

- 中文优先；不用英文栏目名；“路线天气”“活动协作”“现在要做”都是业务词。
- 数字与单位：`12.8 km`、`680 m`、`¥168 / 人`、`07:00`、`18 / 24`、`58–82%`、`8–9 m/s`。
- 时间：发现用“明天 07:00 集合”；详情用“10/24 周六 · 07:00 茶店子客运站”；天气用“10/24 06:00–10:00”；不写“明晚”除非演示时钟确实在前一晚。
- 不写绝对安全：用“更值得关注”“建议在 12:30 前通过”“不替代领队判断”；不写“会有云海/一定安全”。
- 不写平台未具备的能力：不写支付、退款、实时追踪、IM、救援承诺。
- 空态给方向：没有匹配活动 → 清除筛选；没有天气 → 回到活动日；没有协作数据 → 打开主活动；不用“暂无数据”四个字结束。

## 8. 无障碍与交互底线

- 焦点可见：2px 陶土外框，offset 2px。
- 所有图标按钮有 aria-label；所有状态有文字；颜色不是唯一通道。
- 表单 label 与 input 绑定；错误用 `role=alert`；提交按钮在错误时给出字段级提示。
- 弹层 `role=dialog`、`aria-modal`、Esc 关闭、焦点进入首个控件。
- `prefers-reduced-motion` 下禁用动画/过渡。
- 触控：主操作 48px；次级 30–34px；无可见交互元素 <24px（iPhone SE/13/11 Pro Max/Pixel 5 仿真 49/49）。生产建议次级 40–44px 或扩大热区。
- 对比度：正文 ink/paper > 10:1；ink-2/paper > 5:1；ink-3 只用于弱化辅助；陶土/品牌色在浅底上满足 4.5:1 的正文要求需在正式设计 token 中复核。
- 不依赖 hover；所有 hover 动作都有 click/tap 等价。

---

## 9. 动效

- 只做三类：弹层进出（230ms）、按钮按压（120ms）、图表选中/滚动（160–180ms）。
- 不做页面入场编排、不做持续背景动效、不做大面积位移。
- `cubic-bezier(.2,.65,.3,1)`；尊重 reduced motion。
- 阶段推进/任务完成不靠动画解释，靠计数、队列和 toast。

## 10. 迁移到微信小程序

### 10.1 Token 映射

- CSS 自定义属性可直接用于 WXSS；变量挂在 `page` 或根容器。
- 设计稿以 390 为基准；小程序 `750rpx = 屏宽`，换算：
  - 1px @390 ≈ 1.923rpx
  - 20px ≈ 38.5rpx；18px ≈ 34.6rpx；22px ≈ 42.3rpx
  - 12px ≈ 23.1rpx；15px ≈ 28.8rpx；24px ≈ 46.2rpx；48px ≈ 92.3rpx
- 不建议全部写 rpx；正文/线宽/字体可用 px + 系统字体，布局用 rpx。375/414 的差异通过 `page` 宽度计算或 `@media` 等价能力处理。
- 字体：微信端优先 `PingFang SC` / `Songti SC`；Android 用系统 serif 回落；正式验收必须在 iOS/Android 真机检查中文衬线是否可用，必要时用图片标题或统一无衬线。

### 10.2 组件映射

| 原型 | 小程序 |
|---|---|
| `.appbar` sticky | 自定义导航栏 + `position: sticky` 或页面级 fixed；注意胶囊/安全区 |
| `.actionbar` sticky | 页面底部 fixed 容器 + page padding-bottom；键盘弹起时避让 |
| `.sheet` | 半屏弹层组件；`catchtouchmove` 防穿透；授权/审核/分车共用 |
| `.seg` | 自定义 tab/胶囊；不要用原生 tabBar 表达页内筛选 |
| 路线 SVG | 小程序 canvas 或 SVG 组件；坐标从 routeSnapshot 投影；不接真实瓦片时明确“示意” |
| 天气 SVG | canvas 2D 按 DPR 绘制；或用 echarts-for-weixin，但需自定义刻度/注释以保持本规格 |
| 表单 | 原生 input/picker；手机号、紧急联系人、授权分字段；提交幂等 |
| 名单 | 虚拟列表/scrolly-view；21 人演示可直接渲染，正式活动可能更大 |

### 10.3 生产数据契约

- 发现：`ActivitySummary`（id/title/route/startAt/phase/capacity/confirmed/pending/remaining/organizerIntro/fee/difficulty/cover）。
- 详情：`ActivityView` + `DetailState` + `counters` + `permittedActions` + `routeSnapshot` + `pickupPoints` + `feeNote/cancellationNote` + `primarySignupId`。
- 协作：`WorkspaceView`（phase/role/leaderQueue/roster/transport/field/incidents/authorization）+ 阶段门槛 selector。
- 天气：`WeatherView`（activityId/pointId/date/days/detail/series/routePoint/ele/eleSrc/updatedAt/source/limitations）。
- 不在 UI 层重新计算业务状态；用 `journey.participantNext`、`selectors.getDetailState`、`leaderQueue`、`allocation`、`field` 的现有派生。
- 原型 `store.actions` 是本地事务/界面契约：提交、审核、分车、签到、上车、发车、到家、异常、阶段推进都有不变量；生产必须映射到真实 command + 服务端事务，不能把客户端状态当事实。详见 07。

### 10.4 迁移顺序

1. Token + AppBar + Button + Status + Sheet + ActionBar（全局基础设施）。
2. 发现页（数据最窄，最快验证信息效率）。
3. 详情页（复用状态机；补路线图/剖面/报名 sheet）。
4. 协作页（任务队列 + 名单 + 车辆 + 现场；按角色拆组件）。
5. 天气页（路线点/活动窗口/图表/无数据；最后接入真实 Open-Meteo）。
6. 跨页联调（同一活动事实、返回路径、滚动定位）。

### 10.5 迁移红线

- 不改变真实业务规则迁就 UI；不把 pending 算候补、不把司机算乘客、不把签到算上车。
- 不把模拟天气说成真实预报；不写“安全/会有云海”。
- 不在参与者详情暴露全量名单/敏感资料。
- 不把实验控制（阶段下拉、数据状态按钮）带进产品；它们是测试壳。

## 11. Do / Don't

**Do**
- 先事实、后图片；先任务、后明细。
- 一个状态一个主 CTA；一个页面一个主任务。
- 用名单行/时间轴/图表表达关系；用留白和发丝线做层级。
- 数据图给单位、范围、选中、空态、来源。
- 阶段门槛写清楚“还差什么”，而不是只把按钮置灰。

**Don't**
- 不做“纸白 + 衬线 + 细线 + 绿按钮 + 方图”的五件套复制。
- 不把每个区块做成卡片/标签/图标堆叠。
- 不用 4×4 统一座位网格冒充真实车辆。
- 不用精确数字制造虚假天气确定性。
- 不把“查看”按钮铺满名单；不把主行动塞进整卡按钮。
- 不为了首屏塞按钮而压字号、删事实或藏风险。
