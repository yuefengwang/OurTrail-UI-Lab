# 七套视觉方向定义 — Visual Direction Lab

> 本文件是原型实现与评审的**方向契约**：七个候选风格的定义、差异与页面级处方。
> 实现方（原型代码）必须让七套风格在**视觉语言、信息组织、品牌气质**上有实质差异——
> 只换主题色 = 不合格（任务 §10.2 明令禁止）。
>
> 共同约束（任务 §3 尾）：相同业务内容、相同演示数据、相同核心操作、相同页面尺寸、
> 尽可能相同的内容长度与图片素材。**不允许通过删内容、藏操作、降密度来制造不公平优势。**

---

## 0. 与现状的关系（基线背景，2026-10-17 实测）

- 当前生产版本已经完成一轮「**户外编辑式**」重构（19/20 业务页；暖纸面 #F6F3EC、
  石色 #EDE9DE、森林 #163E35、hero 实景封面、kicker/display/fact-row 体系、
  阴影只留浮层）。因此本实验室的候选方向**不是从零开始**，而是回答：
  「现行编辑式方向是否就是终局？还有哪些组织方式更值得投入？」
- **Style A 是对现行编辑方向更彻底的推进**（更严格的排版纪律与编辑节奏），
  其余四个方向是**实质替代方案**（不同的信息组织哲学）；F 为后加的融合方向，G 为后加的忠实镜像方向。
- **Style F（2026-10-18 追加）**：用户在五套复审后要求「取长补短」的第六方向——
  以 A 的编辑骨架融合 B 的纪律层、D 的工具组件、E 的工位组织、C 的状态表达；
  融合决策与排除红线见 `style-F-decisions.md`，按同规格交付、以同口径参评。
- **Style G（2026-10-19 追加）**：用户复审要求「再参照 strava 的风格来一版」的第七方向——
  忠实镜像 Strava 运动视觉语言（橙白、灰阶数据、满幅摄影、读数优先）；
  决策与白名单见 `.omo/style-G/style-G-decisions.md`，按同规格交付与验证、**不参评、不计分**。
- 七套风格都必须在**同一份业务数据、同一批操作**下成立；
  数据语义来源：真实仓库的 Activity/Signup/Vehicle/Member 模型（见 baseline.md）。

## Style A — Alpine Editorial（山野编辑部）

**定位**：精品户外品牌 × 山野杂志编辑部。
**关键词**：克制、自然、精致、编辑感、摄影驱动。
**气质一句话**：像一本认真的户外刊物——内容优先、版式讲究、没有一句废话。

### A.1 设计原则

1. **摄影是第一主角（仅在发现与详情）**：封面承担情绪，文字承担事实；照片之外不出现装饰图形。
2. **排版建立层级**：大小对比 + 留白节奏 + 眉题（kicker）+ 发丝线；禁止用卡片嵌套制造层级。
3. **零卡片化内容面**：区块之间以留白与发丝线分隔；不出现「圆角白卡套圆角白卡」。
4. **指标是句子的一部分**：里程/爬升/名额以事实行（fact row）或行内文字表达，不做仪表盘小卡。
5. **操作低声但清楚**：主操作为实心森林绿按钮，次要操作为文字链；一屏一个主操作。
6. **诚实**：氛围图必带来源脚注；状态词必须有业务语义（来自 journey 词表）。

### A.2 色彩

| 角色 | 值 | 说明 |
|---|---|---|
| 页面底 | `#F7F4EC` | 暖纸面（比现行 #F6F3EC 略深半档，更像纸） |
| 表面 | `#FFFFFF` | 仅弹层与表单区使用 |
| 正文/标题 | `#1B241F` | 近黑的深绿灰 |
| 次要文字 | `#66705F` | 暖灰绿（纸面上 ≥4.5:1） |
| 发丝线 | `#E4DDCB` | 暖色分隔 |
| 品牌/主操作 | `#234B3C` | 深森林绿（比现行 #163E35 略浅、更青） |
| 强调（克制的陶土） | `#A8562E` | 仅用于「临近/截止/今晚」类时间紧迫提示 |
| 叶色 | `#D8E4A0` | 仅照片徽标上的小高亮 |
| 语义色 | success `#2F6B4C` · warning `#8F6A1F` · danger `#A93F33` · info `#46657A` | 全部做「纸面友好」的去饱和处理 |

### A.3 字体与层级（390px 基准）

| 层级 | 规格 | 用途 |
|---|---|---|
| Display | 30px / 700 / 1.25 / -0.3px | 活动大标题、页面主标题 |
| Page title | 26px / 700 / 1.3 | root 页标题 |
| Section | 17px / 600 / 1.4 | 区块标题 |
| Kicker | 11px / 600 / 1.6 / +1.4px 字距 | 区块眉题（本风格签名元素，高频使用） |
| Lede | 15px / 400 / 1.6 | 导语段落 |
| Body | 15px / 400 / 1.6 | 正文（比现行 14px 大一号，阅读优先） |
| Caption | 12px / 400 / 1.5 | 辅助信息 |
| 数字 | tabular-nums | 里程、爬升、时间、名额 |

### A.4 空间与形态

- 间距基元 4px；版心边距 24px；区块间距 32px；段落间距 12px。
- 圆角：图片 2px、按钮 6px、照片徽标 pill；卡片体系尽量不出现，出现时 8px 封顶。
- 边框：只有 1px 发丝线；**无阴影**（弹层除外）。
- 触控目标 44px，操作高度 48px。

### A.5 图像与图标

- 发现：双列大图？不——**单列 16:10 全宽封面**（每张配 kicker 行 + 标题 + 一行事实）。
- 详情：300px hero + 底部 scrim 压字；正文中不再出现第二张大图。
- 图标：1.5px 细描边、20px；克制使用（箭头、分享、位置）。

### A.6 页面处方

**发现（活动发现）— 刊物流**
- 头部：`发现` 眉题 + 编辑部式导语一句（说明排序规则）。
- 筛选：文字游标线 tabs（全部 / 本周 / 轻户外 / 进阶），下划线选中。
- 列表：2–3 个「专题条目」——全宽封面（16:10）、图上日期眉标、标题（Display 级）、一行 lede、
  事实行（`18.6 km · ↑1180 m · 名额 24 · 剩 22`）、文字链 CTA「查看安排 →」；
  其余条目收成紧凑图文行（96px 缩略图 + 标题 + 一行事实）。
- 无卡片边框、无阴影，条目间以 32px 留白 + 1px 线分隔。

**详情（活动详情）— 长文叙事**
- hero（300px 照片 + scrim + 状态徽标 + 日期眉标）。
- 纸面区：Display 标题 → 路线名副题 → 事实行三条（等宽数字）。
- 眉题分区：`行程 / 集合与时间 / 费用与约定 / 同行人 / 装备与提醒`；
  行程为 2–3 段叙事文字 + 关键节点事实行；集合为「事实行」组（地点、时间、车次）。
- 同行人：紧凑行（姓名 + 身份 + 状态词），无卡片。
- 底部 sticky 主操作（报名 / 我已到达，随业务状态切换）+ 诚实性脚注。

**协作（活动协作）— 现场手册**
- 顶部：状态句标题（如「2 人未签到」Display 级）+ 阶段眉题。
- 事实带：集合点 / 出发时间 / 到点人数（三格事实行，发丝线分隔，不做卡片）。
- 分区分组：`集合点 / 成员 / 车辆 / 下一步`；
  车辆以文字行表达（`1 号车 · 4/5 座 · 司机 王屿 · 满员`），座位号以行内文字；
  成员行含出行方式与签到状态词。
- 「下一步」= 编者按式 callout（纸底 + 左侧 2px 森林绿竖线 + 一句话行动）。
- 交互状态：按钮反馈（签到后行内状态词变化）、空态文案、错误态、禁用态各一例。

**天气（扩展页）— 编辑式天气简报**
- 结论句标题（如「周末先雨后晴，清晨有云海机会」）+ 事实行（窗口、温度区间、风）。
- 48h 简表：时间 / 温度 / 降水概率 / 风（文字表格，不画复杂图表）。
- 图表复杂度留给 D 风格验证，本风格只用「简报 + 表格」。

### A.7 预期优势 / 潜在问题

- 优势：品牌感最强；发现页吸引力高；与现行方向同源（迁移成本最低的是它）。
- 风险：协作页效率偏低（信息偏散）；对摄影素材依赖高（活动无实拍图，只能氛围图 + 脚注）；
  若排版纪律不严容易「看起来很贵但不好用」。

## Style B — Swiss Functional（瑞士功能主义）

**定位**：现代功能主义；网格、秩序、精确。
**关键词**：对齐、规则、克制、工具优先。
**气质一句话**：像一份被认真设计过的工程文件——每一条线都有理由。

### B.1 设计原则

1. **网格即秩序**：8px 基线、4 列网格、左对齐；所有元素贴网格，禁止「差不多对齐」。
2. **规则线（rule）取代容器**：分区用 1px 线 + 签名式 2px 强分隔线（section rule）。
3. **层级靠字重与层级位置**：不靠颜色、不靠圆角、不靠阴影。
4. **零圆角、零阴影、零装饰**：容器与按钮全部矩形；浮层也只用线框。
5. **信息可扫描**：表格化行结构；数字右对齐、等宽；单位常显。
6. **一屏一个主操作**；主操作黑、次要操作带线框。

### B.2 色彩

| 角色 | 值 | 说明 |
|---|---|---|
| 页面底 | `#F4F5F3` | 冷中性白 |
| 表面 | `#FFFFFF` | 表单/表头用 |
| 正文 | `#101413` | 近黑 |
| 次要 | `#5A615D` | |
| 线 | `#D7DAD6` | 常规 1px |
| 强线 | `#1E2321` | 2px section rule（签名元素） |
| 品牌/主操作 | `#16201C` | 近黑绿（按钮黑底白字） |
| 状态 | success `#1F7A4D` · warning `#A96B00` · danger `#B3372B` · info `#2C5F7C` | 仅文字/细边框，不做大面积填充 |

**无装饰强调色**——本风格的「品牌感」来自排版本体。选中/激活态用黑色下划线或黑色文字。

### B.3 字体与层级

| 层级 | 规格 |
|---|---|
| Display | 28px / 700 / 1.2 / -0.4px |
| Section rule 标签 | 12px / 700 / +1px 字距（中文）/ 顶部 2px 线 |
| Body | 14px / 1.55 |
| Caption/单位 | 11px / 500 / +0.5px |
| 数字 | tabular；表格中右对齐 |

### B.4 空间与形态

- 8px 基线；页面边距 20px；行高 44–56px；区块间距 20px（紧）。
- 圆角全部 0（chip 也 0 或 2px 边框矩形）；无阴影。
- 表格：行发丝线、表头 11px 大写字距标签。

### B.5 图像与图标

- 图像**功能性使用**：列表行内 56px 方图 + 2px 直角；详情首图 180px（压暗、矩形）；
  协作页无图。图片永远不与文本争夺层级。
- 图标 16px/1.5px，仅作行内功能标记；不做装饰。

### B.6 页面处方

**发现 — 活动索引表**
- 头部：`活动索引` + 排序说明（按出发时间）。
- 工具栏：下划线 tabs（全部/可报名/本周）+ 下划线搜索框，一行位置。
- 行结构（签名）：`[日期块 MM/DD + 周X 两行 tabular] | 标题 + 路线（两行） | km·↑m（tabular 右对齐） | 状态（1px 边框矩形） | →`；
  行间 1px 线；无图版本（可选 56px 方图版本二选一，本风格默认无图、纯网格）。
- Featured 活动：以**表格化的"头条行"**表达（大标题 + 完整事实格），不做大图。

**详情 — 规格表**
- 顶部：标题块（Display）+ 右侧状态；其下**参数网格**（2 列 × 4 行：出发/结束/报名截止/集合/名额/费用/难度/领队，标签左灰、值右）。
- 分区：2px section rule + 标签；行程 = 编号节点行；要求 = 复选框式清单表格；
  同行人 = 表格（姓名/身份/出行/座位/状态）；费用 = 明细行 + 合计行。
- 底部 sticky 方角操作条（主操作黑）。

**协作 — 运营控制台**
- 顶部：阶段 + 三格计数（待审核/待安排/待签到，tabular 大数），线划分格。
- 控制：下划线 segmented（总览/名单/分车/现场）。
- 名单：表格（姓名/出行方式/座位/状态/操作），行高 44px；
- 分车：车辆块 = 标题行（车牌/司机/容量）+ 座位矩阵（4 座 + 过道，正方形格、数字居中、边框线）；
- 现场：签到清单 = 大方格 checkbox + 姓名 + 时间；
- 下一步：单一规则行（label + 行动 + →）。
- 状态一例：表格行的禁用态（灰字 + 不可点）、空态（规则行内说明）、错误态（顶部红黑条）。

**天气 — 预报矩阵**
- 表格优先:时间行 × 列（温度/降水/风/云量），表头带单位；选中行黑底反白。
- 窗口结论：一行强线总结（`出发窗口：周日 06–10 时，晴，风 3 m/s`）。
- 折线图只作为表格附属（细线、无填充）。

### B.7 预期优势 / 潜在问题

- 优势：协作/表单/名单页效率最高；组件复用与长期维护最好（纯规则、无魔法值）。
- 风险：缺乏户外温度（冷、硬）；发现页吸引力弱；对排版执行精度要求极高，
  否则「精确」会退化成「简陋」。

## Style C — Quiet Terrain（静野）

**定位**：安静、自然、成熟的户外生活方式产品。
**关键词**：低饱和、自然材质、温和、耐看。
**气质一句话**：像清晨雾里的山径——不抢注意力，但待久了很舒服。

### C.1 设计原则

1. **低刺激**：无高饱和色块、无强对比；层级靠字重、色调过渡与空间。
2. **色调分组**：用相邻的「淡色调带」（雾灰/麻布/苔绿）分组内容，而非卡片边框。
3. **阅读优先**：正文 15px/1.65、行宽克制；长内容（详情/天气简报）是本风格主场。
4. **克制的强调**：主操作是低饱和苔绿实心按钮；状态以「文字 + 小圆点」表达，不做彩底标签。
5. **不做伪材质**：不用纹理/纸张贴图假装高级；材质感来自颜色与光感本身。
6. **节奏均匀**：留白均匀分布（不使用戏剧性大间距制造高潮）。

### C.2 色彩

| 角色 | 值 | 说明 |
|---|---|---|
| 页面底（麻布） | `#F1EFE8` | |
| 表面（晨雾） | `#F8F6F0` | |
| 色调带（雾灰） | `#E8E5DB` / `#EDEAE1` | 分组用 |
| 正文 | `#303630` | 深苔灰 |
| 次要 | `#707668` | |
| 线 | `#DFDCD0` | 低对比发丝线 |
| 苔绿（品牌/主操作） | `#4C5F49` | 去饱和的森林绿 |
| 语义色 | success `#55755A` · warning `#8F7345` · danger `#9C5A50` · info `#5B7080` | 全部蒙尘处理 |
| 禁用/待定 | `#A9A89B` | |

### C.3 字体与层级

| 层级 | 规格 |
|---|---|
| Display | 26px / 600 / 1.35 / 0 |
| Section | 16px / 600 |
| Kicker | 12px / 500 / +0.6px / 次要色 |
| Body | 15px / 400 / 1.65 |
| Caption | 12px / 400 / 1.6 |
| 字重≤600 | 不使用 700+（避免喊叫感） |

### C.4 空间与形态

- 间距基元 4px；边距 22px；区块间距 28px；行高舒适（56px+）。
- 圆角：图片 10px、按钮 10px、色带条 12px；**整体软化**。
- 边框：1px 低对比线；无阴影（浮层用遮罩淡入）。
- 触控目标 48px（比常规更大，宁松勿紧）。

### C.5 图像与图标

- 图片做**降饱和处理**（实验室用 CSS filter 演示；生产需预处理图片，记迁移任务）；
- 缩略图 88px 圆角 10px；详情 hero 220px 柔和 scrim（不用深黑压底，用「苔绿雾」压底）。
- 图标 1.5px / 20px / 次要色。

### C.6 页面处方

**发现 — 平静清单**
- 头部：大标题 + 一句说明（不含营销词）。
- 「最近出发」**色调带**块（雾灰底、圆角 12px，块内：活动名 + 时间 + 名额一句话 + 文字链）。
- 其余条目：留白分隔（**不用线**）：88px 缩略图 + 标题 + 两行次要事实 + 状态词
  （`还可报名 · 剩 12`，纯文字）。
- 搜索与筛选折叠为一行次要控件（描边细圆角）。

**详情 — 舒缓叙事**
- 220px hero + 标题 + lede；区块以留白 + kicker 分节；
- 行程 2–3 段散文；事实行（`出发 / 集合 / 截止`）为「标签 + 值」安静两列；
- 同行人紧凑行；集合点块：雾灰底圆角块（地点/时间/一句话）；
- sticky CTA 苔绿；诚实脚注保留。

**协作 — 待办清单**
- 顶部安心句（`集合还有 1 天 · 2 人未签到`，Display 级 600）；
- 色调带分节：集合点带 / 成员清单（行 + 状态词 + 小圆点）/ 车辆（文字行）/ 下一步（雾灰块 + 一句行动）；
- 签到交互：勾选后状态词变为「已签到 · 22:41」并降权（文字变淡）；
- 空态/禁用态：文字说明 + 低饱和图标，无红色恐慌（错误态用砖玫瑰色文字而非红块）。

**天气 — 温柔简报**
- 结论句 + 「这周末」三段自然语言（明天/后天/大后天）；
- 小尺寸细线温度曲线（单色、无填充）；
- 窗口以安静文字行列出；低刺激配色验证「信息密度不足时是否仍然成立」。

### C.7 预期优势 / 潜在问题

- 优势：耐看、友好，适合广泛户外用户；长内容阅读体验最好；对摄影素材要求最低（降饱和后更宽容）。
- 风险：对比不足会显得平淡、降低信息辨识度；CTA 可能不够抢眼；
  在强光户外环境下（手机屏幕）低对比是真实可用性风险——评审时必须核对比度。

## Style D — Field Instrument（野外仪表）

**定位**：专业户外工具。
**关键词**：地形、数据、导航、可靠。
**气质一句话**：像手持 GPS / 海拔表的界面——出发前看它，出发后也看它。

### D.1 设计原则

1. **数据即界面**：海拔、距离、时间窗、集合点、座位是界面主角；文字标签（含单位）永远成对出现。
2. **可扫描、可比较**：同类数据用同一格式、同一对齐、同一精度；能对齐的多行数字必须 tabular 对齐。
3. **功能性图形**：等高线/剖面/云带/风羽只在承载数据时出现；禁止纯装饰的地形纹理。
4. **紧凑而不挤**：小字号 + 高密度 + 严格分组线，信息密度是特性不是缺陷。
5. **状态可判读**：LED 式状态点 + 标签（正常/注意/中止），颜色单义。
6. **不做仪表盘卡片墙**：数据以「标签-值-单位」行与表格组织，而不是把小数字包装成卡片。

**发现 — 出征表**

- 状态头：阶段大读数（`2 人未签到` 28px）+ 倒计时；
- 读数栅格：到点 5/12 · 已上车 3/4 · 候补 1（三格，线分）；
- 集合点块（含坐标、时间、到点比例条）；
- 成员扫描表（行：姓名 / 出行方式 / 座位 / 签到状态点 + 复选框交互）；
- 分车：每车座位矩阵（4+过道、方格、数字、司机格反白）；
- 下一步：单行行动条（`发起出发确认` + →），失败/禁止态以状态点变色 + 行内原因说明。

**天气 — 全站数据主场**
- 48h meteogram（温度线、降水柱、风羽、云带停留层、时间轴）；
- 关键窗口表（行：时段 / 温度 / 降水概率 / 风 / 云 / 判定）；
- 海拔与站点信息行；所有数值带单位；`YOU` 位置锚点；
- 图表失败/数据缺失：显式「数据缺失」占位（本风格必须表现「数据不可用」也是信息）。

### D.7 预期优势 / 潜在问题

- 优势：天气/路线/集合协作页面表现力最强；信息密度与专业性高；「可靠工具」心智与产品定位（纯工具）最一致。
- 风险：作为全站唯一语言过于技术化、缺乏情绪价值；发现页吸引力依赖 UI 之外的内容质量；
  数据不足时（弱数据活动）界面会显得空和冷。

## Style E — Expedition Modern（远征现代）

**定位**：现代远征品牌。
**关键词**：行动力、装备感、鲜明排版、有限强对比。
**气质一句话**：像一件好装备的吊牌——信息清楚、力量感强、想立刻出发（但日常徒步也不违和）。

### E.1 设计原则

1. **强对比色块分区**：岩石深色块（页头/状态区）与自然浅底交替，构成「章法」；不用渐变。
2. **编号与大字**：路线编号（R-018）、章节编号（01/02）、大数字（名额/人数）是版式骨架。
3. **行动入口显性**：主 CTA 是全宽深色条或高对比块；次操作窄而安静。
4. **有限强调色**（远征黄）：只用于编号、关键状态、重点数字下划线；**严禁大面积**。
5. **日常友好**：轻户外活动用同一语言但降级对比（浅色块版本），不为每个活动都摆出派头。
6. **不学游戏 HUD**：无发光、无科技感网格、无拟物金属。

## Style F — Trail Works（山野工坊）

**定位**：编辑品牌的工具化深化——「刊物工艺 × 工位纪律」。
**关键词**：融合、纪律、工位、台账、纸感。
**气质一句话**：像一间山野工坊的工作台——刊物级的排版工艺，配上可信、顺手的工具台账。

### F.1 设计原则

1. **编辑骨架（承 A）**：刊物节奏（眉题 → 大标题 → 导语 → 事实行）、暖纸面、直角纪律、摄影纪律；页面结构与 A 同规格可比，密度全线升级。
2. **数字纪律（承 B）**：数字右对齐、单位常显、表格化扫读；全站一套形体规则，几乎无判例外元素。
3. **工具组件（承 D）**：海拔剖面、窗口与逐时判定表、`YOU` 锚点、出发倒计时——只在工具场景出现，且一律过「纸感滤镜」（墨色线，无仪表灰）。
4. **工位组织（承 E）**：分区即工位（编号 + 名称 + 右侧计数）；活动工位加 2px 墨线；分区操作条承担页内动作。
5. **状态表达（承 C）**：空 / 错 / 禁用以文字色与留白表达，绝不做红色块；锈色只表警示（白名单：待安排车辆 / 临期倒计时 / 失败态文字 / 降雨条）。
6. **融合红线**：不是皮肤拼贴——每件嫁接物须过纸感滤镜与全套评审；排除 B 的冷皮肤、E 的深色重块与长滚结构、D 的 13.5px 小字 chrome、A 的整条图片管线；唯一允许的深色块 = 主操作实心底（CTA 绿）。

| CTA 绿 | `#1C4433` | 只给主操作实心底（唯一深色块） |

**天气 — 气象单**
- 判决块（云海机会：文字判定）→ 48h 曲线（墨色线 + 提示框读数 + 云海短条）。

## Style G — Strava Athletic（橙白运动风）

**定位**：运动社交产品视觉语言（Strava 忠实镜像）。
**关键词**：橙白、数据优先、满幅摄影、读数（tabular）。
**气质一句话**：像一款成熟的运动社区 App——照片给情绪、橙色给动作、数字给事实，克制到近乎冷峻。

### G.1 设计原则

1. **忠实镜像（2026-10-19 增补）**：参照 Strava 公开产品视觉语言的第七方向；按同规格交付与验证（四页 × 三视口、同数据同操作），**不参评、不计分**（评分轮保持既有 A–F 口径；决策与白名单见 `.omo/style-G/style-G-decisions.md`）。
2. **橙的三个角色互斥**：品牌橙 `#FC5200` 仅图形通道（实心 kudos / 路线折线 / 激活指示条 / PR chip 底）；CTA 橙 `#CC4200` 承担品牌文字与白字实心按钮（4.83:1）；浅橙 `#FC6100` 限量强调（featured 卡顶规 / tab 悬停指示）。一屏橙色实心块 ≤2。
3. **数据优先**：32/700 大读数与三联读数是页面骨架；白卡即内容单元，不做嵌套卡片墙。
4. **摄影满幅、零滤镜**：头图与 hero 同档满幅出血；照片不加滤镜（`--lab-photo-filter: none`）。
5. **形态纪律**：按钮 4px、卡片 8px、chip 全圆（pill）；内容面零阴影；发丝线只作装饰，功能描边走三级墨。
6. **状态不另起炉灶**：语义状态色沿用 A–F 既有字面量（success `#2F6B4C` · warning `#8A6A20` · danger `#A0402F` · info `#44647A`）；状态页用白卡 + Asphalt 弱化文字，不落红色警报块——红只留给真实危险（取消 / 失败）。
7. **字族两轨**：展示层（刊头 / 卡名 / 大读数 / 图表标注）经 `--g-sans`（Inter 置首、逐级回落共享栈）；正文消费共享 `--lab-font-family`；kicker 行高绑定共享 `--lab-body-lh`（与 F 同型，审计备案）。

### G.4 空间与形态

- 间距基元 4px；版心边距 16px（与 D 并列最紧）；区块间距 20px；行位 56px。
- 圆角：图片 10px、按钮 4px、卡片 8px、chip 全圆（pill）。
- 阴影：内容面零阴影；浮层 `0 8px 24px rgba(36,36,40,.14)`。
- 触控 44px；操作高度 48px；图标 20px / 2px 描边；动效 180ms（快档 120ms）。

### G.5 图像与图标

- 摄影满幅、零滤镜（`--lab-photo-filter: none`）：feed 卡头图 200px 满幅出血，hero 同档；加载后淡入。
- 头像 40px 圆形（成员行 / kudos 行）；橙色只属于图形元素（kudos 实心 / 折线 / 指示条）。
- 图标 2px / 20px，行内功能标记与读数并列。

### G.6 页面处方

**发现 — Feed 流**
- 满幅刊头（wordmark + 城市 + 三联读数）→ 满幅筛选 tab（滑动橙指示条）→ 满幅搜索 → feed 卡流（头图 → 三联读数 → kudos 行）→ 脚注。

**详情 — 档案页**
- 满幅 hero（照片 + 品牌旗）→ 白底标题区 → 状态行 → factstrip（32/700 大读数 + 三联）→ 路线折线 → 行程叙事 → 装备清单 → 费用 → 同行人 → 报尾 sticky 主操作。

**协作 — 分段控制台**
- 满幅抬头 → 只读说明 → 分段 tab（总览 / 名单 / 分车 / 现场）→ 现场六格 + 进度条 → 名单与分车（成员行 / 分车格 / 座位矩阵）→ 下一步。

**天气 — 数据简报**
- 满幅简报（地点 + 结论）→ 出发窗口规格行 + 决策条 → 48 小时曲线 + 读数面板 → 日卡（按日分组）→ 窗口判定 → 来源 → 脚注。

### G.7 预期优势 / 潜在问题

- 优势：运动激励与社交节奏成熟（满幅摄影 + 三联读数 + kudos 的组合被大规模验证）；形态纪律（零阴影、小圆角、pill chip）实现与替换成本低。
- 风险：品牌语言源自他方产品——作为方向参照保留，是否启用属后续产品决策；三档橙的纪律一旦失守会立刻显得廉价；白画布 + 高饱和橙对本产品「山野自然」语境的中性适配待真机与用户验证。

## 5. 实现契约（给原型实现方）

1. **同一数据源**：`prototype/js/data.js`，七风格只读不改；禁止在某一风格里删减字段。
2. **同一操作集**：发现页筛选/搜索、详情页 CTA（状态切换）、协作页签到/状态演示、
   天气页时段切换——每风格都必须实现，允许形态不同（按钮/行内链接/色块）。
3. **令牌驱动**：组件 CSS 只消费 `--lab-*` 令牌；风格差异的 80% 应能通过令牌表达，
   剩余 20%（布局与结构）写在各风格的 CSS 与渲染函数里。
4. **结构差异是硬要求**：每风格的三个页面必须使用**不同的 DOM 组织**（不是同一组件树换皮肤）。
5. **WXSS 兼容纪律**（为迁移可信度）：不使用 `color-mix()` 运行时混合、不使用 `:has`、
   不依赖 `backdrop-filter`、全角值一律字面量（令牌即字面量）；布局避免 `position: sticky` 以外的
   复杂滚动技巧。**仅在纯装饰的实验室外壳中允许放宽**（外壳不进迁移）。
6. **状态完整性**：每个页面至少有 正常 / 空 / 错误 / 禁用、加载中 的适当示例
   （不必每页全部，但全局都要能看到）。
7. **诚实边界**：演示数据必须可识别（footer 或 lab 面板注明「演示数据」）；
   不假装已接通后端。
