# F 方案精修参考（2026-10-20）

> 状态：**锁定 F**，但暂不改代码。先回答两个问题：
> 1. 从「橙白运动风（G）」能拿什么经验？
> 2. 市面上有哪些成熟 App 能给 F 提供参考？
>
> 结论：**F 的问题不是“不够花”，而是“暖色过多、层级过散、编辑虚构过多”。**  
> 正确动作：保留 F 的纸面/森林/陶土，借 G 的读数纪律，借成熟户外/协作产品的信息语法；**不要借 G 的橙色品牌与白卡墙**。

---

## 1. 从 G 拿什么、不拿什么

| 拿走（F 需要） | 具体做法 | 不拿走 |
|---|---|---|
| 一个主读数 | 发现页主推只留 1 个主角数字（距离或名额），其余做辅助；详情首屏主读数是距离/爬升；协作首屏是「3 人未签到」 | 不把每个数字都做大 |
| 数字/单位/标签三级 | `18.6`（大）`km`（小）`全程`（更小）；tabular；单位不省略 | 不做运动成绩/个人纪录 |
| 路线剖面一等公民 | 详情首屏下方直接给海拔剖面 + 关键点 + 距离/爬升，不只放一张路线图 | 不把剖面做成装饰图 |
| 单一实心 CTA + 一个次级动作 | 主 CTA 实心森林绿；分享/天气用线框或文字；一屏只一个 primary | 不做橙色 CTA；不做多个同权按钮 |
| 满幅照片、零滤镜 | 发现/详情 hero 使用真实照片，日期/状态压在图上 | 不把白卡叠在照片上 |
| 稳定的间距/圆角/卡片节奏 | 采用 G 的节奏一致性，但只在“数据面板/车辆/弹层”使用卡片 | 不做白卡墙；不用 01–06 编号把所有区块压成同一种容器 |
| 状态先行 | 先写“报名中 / 余位 3 / 今晚截止”，再谈颜色 | 不让橙色同时承担品牌、状态、CTA、路线、数据强调 |

**G 的隐性代价**：G 是 Strava 的忠实镜像，语言是“运动社交/成绩 feed”；OurTrail 是“私域熟人活动履约”。  
借读数可以，借品牌会让人期待 kudos、个人纪录、公开路线这些不存在的产品能力。

## 2. 成熟 App 参考矩阵

> 参考的是**信息结构、数据语法、任务组织**，不是视觉皮肤。  
> 下列产品都不应整包照抄；每条都写明“借什么/不借什么”。

| App | 借什么 | 不借什么 | 对 F 的页面 |
|---|---|---|---|
| **Komoot** | 以路线为中心的发现与规划；运动类型/难度/距离筛选；路线集合与高亮点的组织方式 | 社区 feed、付费路线包、欧洲语境的活动语气 | 发现、详情 |
| **AllTrails** | 路线事实的完整语法：距离、爬升、难度、海拔剖面、路况/评价、离线地图；首屏“能不能走”的判断顺序 | 订阅推销、通用绿色主题、UGC 评价墙 | 详情、天气 |
| **FarOut** | 长线指南书式内容 + 离线 waypoint/水源/营地/风险；长文与现场可用性并存 | 纯长文、无任务入口、过密文字 | 详情、现场 |
| **Spond** | 群体活动的报名/出席/名额/提醒；“谁还没回应”作为第一类信息 | 青少年俱乐部/家长管理结构、缴费体系 | 协作、报名 |
| **TeamSnap** | 名单、可用性、角色、赛程；把“人”和“状态”放在同一张表里 | 企业/俱乐部后台的复杂权限与账单 | 协作、名单 |
| **Wanderlog** | 地图 + 行程一屏；多人共同编辑同一份计划；地点/路线/备注的关系 | 机票酒店预订、旅游攻略社区 | 详情、协作 |
| **Strava（G 的来源）** | 读数语法、路线剖面、单一 CTA、满幅照片 | 橙色品牌、运动社交/成绩/kudos、公开 feed | 四页的工艺层 |
| **Linear / Things（工具类，非户外）** | 任务队列的优先级、单行动、完成反馈；列表的扫读节奏 | 开发工具语言、深色工程感 | 协作任务区 |

### 2.1 最重要的三个参考

1. **AllTrails 的“路线事实页”**：F 的详情页应该像它一样先回答“多远、多高、多难、路况如何”，再讲活动故事。
2. **Spond 的“谁还没回应”**：F 的协作页应该把“未签到/未分车/待审核”做成第一屏主读数，而不是先摆车辆网格。
3. **Komoot 的“路线集合”**：F 的发现页应该是“路线索引”，不是“第 03 期杂志”；用路线/区域/难度组织，不用虚构编辑栏目。

## 3. F v2 的具体精修配方

### 3.1 色调：先解决“暖色糊在一起”

当前 F 的纸面、燕麦、锈色、森林都偏暖；暖色面积过大时，层级会靠“更深一档的棕”来区分，容易显得脏、旧、没有重点。  
建议把颜色分成 4 个明确角色，减少“又多一个米色”：

| 角色 | 建议值 | 用法 | 约束 |
|---|---|---|---|
| 纸面 | `#F6F3EC` | 页面底 | 保持暖纸，但比 `#F5F1E5` 更中性 |
| 石色 | `#E8E3D7` | 分区带/表头/数据底 | 只做一层，不再叠第二层米色 |
| 墨色 | `#1B241F` | 正文/标题 | 对比拉满 |
| 森林 | `#1E3D32` | 品牌/主 CTA/路线/阶段 | F 的结构色，不用于大面积背景 |
| 深森林 | `#16352B` | 协作指挥带/hero 压底 | 只给“指挥/压底” |
| 陶土/锈 | `#A4562F` | **只给**截止、名额紧张、异常、风险 | 不用于品牌、不用装饰 |
| 叶色 | `#D6E3A4` | 小面积状态/高亮 | 只做点，不做底 |
| 石板蓝 | `#4F6871` | 天气数据/云底/图表 | 只在天气页，给数据一个冷静通道 |
| 发丝线 | `#D8D2C3` | 分隔 | 比现在更清楚 |

比例：纸/石 70% · 森林 20% · 陶土 5% · 叶/石板 5%。  
**不要**把 G 的橙色 `#FC5200` 引入 F；它会把“风险/截止”的语义通道抢走。

### 3.2 字体与文案：把“杂志社”删掉

- 衬线只给活动名/hero 标题；区块标题、标签、按钮、数据全部无衬线。
- 正文 15px；辅助 12px；数字 tabular；单位比数字小两档。
- 一屏只允许一个主读数：发现页主推「18.6 km」或「余位 3」二选一，不要把距离、爬升、名额、费用都做成同权大数字。
- 删除所有虚构编辑内容：
  - `发现 · 第 03 期`
  - `本期头条`
  - `每期由领队与编辑共同挑选，没有广告位`
- 换成真实业务语言：
  - `下一场`
  - `按出发时间`
  - `路线与集合`
  - `现在要处理`
  - `出发窗口`
  - `谁还没签到`
- 借用 G 的短标签，但换成语义：`出发窗口`、`名单与分车`、`下一步` 这类词比“第 03 期”有用。

### 3.3 页面级改法

**发现**
- hero：满幅照片 + 日期/状态压在图上 + 活动名 + 3 个事实（距离/爬升/费用）+ 余位/截止 + 一个主 CTA。
- 索引：密集行，不再 2–3 张“专题大卡”；行内用日期/标题/路线/距离/难度/费用/状态。
- 筛选：可报名/已成行/已结束（来自真实数据），不做“第 03 期”/“本周专题”这类假栏目。
- 主读数：只突出一个数字（距离或余位），其余做事实行。

**详情**
- 首屏：活动名 + 日期/集合 + 距离/爬升/难度/费用/余位；一个主 CTA。
- 路线：真实地图（生产已有）+ 海拔剖面 + 关键点；剖面是数据，不是装饰。
- 后续：行程 → 装备/风险 → 领队/同行 → 费用；用纸面分区，不要 6 张白卡 + 01–06 编号。
- 主读数：`18.6 km` 或 `1,180 m` 选一个作为视觉锚；另一个做辅助事实。
- 参考 AllTrails 的“路线事实页”顺序，参考 FarOut 的 waypoint 备注，但不要写成旅行攻略。

**协作**
- 首屏标题用「3 人未签到」这类状态句，而不是「集合与分车」。
- 指标：待审核 / 未签到 / 未分车 / 异常；每个数字必须带分母或解释（例如「未签到 3 / 15」）。
- 任务队列在首屏；名单/车辆/现场在任务之后。
- 车辆用真实核载/司机/座位；不做 4×4 统一格。
- 参考 Spond 的“谁还没回应”、TeamSnap 的名单/角色，参考 Linear 的任务优先级；不要用工程后台语言。

**天气**
- 首屏标题用「出发窗口 周日 06:00–10:00」或「午后阵雨，建议 12:30 前通过」，而不是「天气」。
- 路线点/海拔/活动窗口是主变量；图表是证据，不是装饰。
- 数据来源/不确定性/模拟标注常驻；颜色用石板蓝做数据通道，陶土只做风险。
- 参考 AllTrails 的 trail conditions 结构、D 风格的窗口表；不要把所有变量平铺。

### 3.4 可以立刻借用的 6 个具体模式

1. **AllTrails 的“路线事实带”**：距离/爬升/难度/预计时间四项，单位常显。
2. **G 的“主读数 + 单位 + 小标签”**：一屏一个主数字。
3. **G 的“单一实心 CTA + 一个线框次级”**：不把分享/收藏/更多挤成同权按钮。
4. **Spond 的“未响应人数”**：把协作首屏变成“谁还没做”，不是“有什么组件”。
5. **TeamSnap 的“名单行 = 人 + 角色 + 状态 + 动作”**：一行解决一个人。
6. **Komoot 的“路线集合”**：发现页用路线/区域/难度组织，不用虚构期号。

## 4. F v2 先做什么（不改代码）

建议顺序：

1. **F v2 参考板**：把 AllTrails 的路线事实页、Spond 的出席摘要、G 的读数/CTA、Komoot 的路线集合各截 1 个结构示意，和 F 当前页并排，先对齐“借什么”。
2. **F 发现页 + 详情页**：这两页决定品牌与决策；先做，验证“去杂志化 + 主读数 + 路线剖面”。
3. **F 协作页**：把“3 人未签到”做成首屏主读数，再接名单/车辆/现场。
4. **F 天气页**：先做“出发窗口”摘要，再决定图表/表格。
5. 每页都做 375/390/414 + 关键状态；不改共享 tokens/组件，直到 F 定稿。

> 不建议现在新增第八套风格，也不建议把 G 的橙色带进 F。F 的问题是“精修”，不是“换方向”。
