### 1.3 间距与布局

- 间距基元 4px（沿用现有数值体系）；版心边距 24；段落间距 12。
- 区块间距：现行 28 → A 建议 **32**（编辑节奏）；是否调整以真机密度复核为准。
- 布局纪律：**零卡片化内容面**（区块靠留白 + 发丝线分组）；列表行高 64（人物行）/ 56–64（活动行）。

### 1.4 圆角、边框、阴影

- 圆角：图片 2 / 按钮 6 / 照片徽标 pill；**卡片体系尽量不出现，出现时 8px 封顶**（现状 button 8 / card 14 → 收敛）。
- 边框：只有 1px 发丝线。
- 阴影：**内容面零阴影，只留浮层**（现行纪律保留）。

### 1.5 图标与图片

- 图标：1.5px 细描边 / 20px，克制使用（箭头、分享、位置）；icon 组件（SVG data-URI）保持唯一叶子。
- 图片：现行 9 张 Unsplash 氛围图管线（稳定散列 + 失败回退 + 页脚诚实脚注）**保留**；
  真活动实拍图 = 服务端 schema 变更（活动模型加图片字段 + 上传链路），**必须走 ADR**，不在本方案自动实施。

### 1.6 基础组件规范

| 组件 | 规范 |
|---|---|
| 按钮（主） | 实心森林绿 / 高 48 / 圆角 6；**一屏一个主操作** |
| 按钮（次） | 文字链或细描边；不与主操作争注意力 |
| 输入框/表单 | 分区 + 发丝线；校验信息就近显示；错误反馈不弹窗轰炸 |
| 列表行 | 事实行模式（`18.6 km · ↑1,180 m · 名额 24 · 剩 7`）；数字 tabular |
| 状态标签 | 状态词来自 journey 词表；A 用小字+色字，不做彩底大标签 |
| 眉题/kicker | 全站统一类（既有 `.kicker` 升级为 A 规格） |

### 1.7 业务组件规范

| 组件 | 规范（以实验室同源实现为准） |
|---|---|
| 活动卡片 | 普通卡 = 缩略图 + 标题 + 一行事实；Featured = 全宽 16:10 封面 + 眉标 + 事实行 + 文字链 CTA；**不出现卡片边框** |
| 成员信息 | 紧凑行：姓名 + 身份 + 出行方式 + 状态词；无卡片、无头像墙 |
| 集合点 | 事实行组（地点 / 时间 / 车次）+ 下一步 callout（纸底 + 2px 品牌竖线）；借用 D 的坐标/比例条用于协作页 |
| 车辆与座位 | 文字行表达（`1 号车 · 4/4 座 · 司机 王屿 · 满员`）；座位矩阵保持硬规则（每排 4 座 + 16px 过道）；座位交互沿 B/D 的方格制 |
| 工具页数字纪律（借 B） | 数字右对齐、单位常显、表格化行结构（用于名单/分车/表单/结算类页面） |
| 天气/路线表达（借 D） | 剖面式图形、窗口表、`YOU` 锚点、单位常显——用于 P4 专业页 |

### 1.8 空/错/加载/禁用状态规范

- 四态齐备（status-panel 已有四态，视觉升级对齐 A：低恐慌、说明句 + 单一动作）。
- 按钮反馈链：点击 → 加载中 → 终态（toast + 按钮态变更），实验室已验证七套模式可迁移。
- 禁用态：说明原因（如「签到已锁定」），不灰死不给理由。

### 1.9 页面层级与导航

- tabBar 四 tab（活动/天气/通知/我的）不变；**统一的是视觉规则与交互原则，不是页面结构**。
- 页面节奏：kicker 分区 → display 标题 → 内容块（32 间距）；长页每 2–3 屏一个视觉锚点。

### 1.10 亮色/暗色模式策略

**本阶段不纳入暗色模式**：项目当前无暗色需求、原型未验证、且小程序双主题会显著放大迁移面。若未来需要，另立 ADR + 独立实验，不复用本方案。

## 2. 页面重构顺序（P0–P4）

> 依据真实审计（`baseline.md`）：现行生产已有编辑式基础（19/20 页完成过一轮），本方案是在**冻结主风格语言（A，或真机对比后的 F）**后做「对齐 + 补齐」。
> 顺序按：曝光度 × 转化价值 × 风险（先低风险高价值）。

| 批次 | 范围 | 内容 | 前置 |
|---|---|---|---|
| **P0** | 基础层 | app.wxss 令牌升级（§1.1/1.2 微调）+ 全局类（kicker/display/fact-row 升级）；令牌登记 artifact（skill） | 主风格定稿（真机 A／F 对比） |
| **P1** | 高曝光 | `home`、`discover`、`activity`、`activity-card` 组件——对照 A 语言复核 + 细节收敛（正文 15px、间距 32、卡片化收敛） | P0 冻结 |
| **P2** | 转化与创建 | `signup`（分步 + sticky 提交）、`editor`（798 行，改动面最大） | P0；建议 P1 之后（复用已验证模式） |
| **P3** | 高频协作工具 | `workspace` + roster/transport/field 面板 + `vehicle`、`staff`（staff 零事件薄壳；改动前先补测试） | **先冻结 trip2/golden-path 门禁读数** |
| **P4** | 专业信息 | `weather`、`weather-hub`、`weather-chart`（先冻结 weather-page-test 189 条）；`route`、`routes`、`route-edit`（借用 D 表达） | 天气门禁冻结 |
| **P5** | 长尾 | `me`、`notices`、`anotices`、`privacy`、`lab`/DEV 页不纳入 | P0–P4 完成后顺带 |

注：任务建议的 P1「发现/详情」与 P2「协作」顺序已按审计事实调整为「P1 高曝光 → P2 转化 → P3 协作」——signup/editor 是转化关键且上一轮未重构（`baseline.md` §4.2），与 P3 交换；理由记录于此。

## 3. 每批实施边界（任务 §6.3 逐项落实）

每批必须满足（写进批次任务书头部）：

1. **明确页面范围**：只改批次清单内文件；跨批次文件（app.wxss、公共组件）改动必须列入 P0 或本批显式申报。
2. **业务逻辑保护清单**：引用 `baseline.md` §5（路由注册、授权、活动流程、成员/领队状态、车辆座位、天气契约、表单校验、门禁读数）；本批涉及项逐条勾选。
3. **复用冻结令牌与组件规范**：不许引入新色/新字号/新圆角（新增一律走令牌登记流程 + 复核）。
4. **视觉对照 + 行为回归**：改前/改后同内容截图对照（390 真机）+ 对应 scenario 测试全绿。
5. **契约不变**：接口、数据结构、权限语义零变更；封面类 schema 变更走 ADR。
6. **留痕**：每批结束记录「已完成 / 未完成 / 无法验证」三态清单。
7. **并发纪律**：`app.wxss`、公共组件、全局类同一时间只能有一个 Agent ≡一个 worktree 修改（PARALLEL_DEV 约定）；不推 master。

## 4. 每批回归验收标准（统一门禁）

| 层 | 标准 |
|---|---|
| 静态 | `node tools/check.js`、`check-handlers.js` exit 0；无未登记的新颜色字面量 |
| 构建 | 开发者工具编译通过；主包 ≤2MB（当前 1,646KB，含 525KB 照片；**图片预算单列**，新增图片必须先算包体） |
| 交互 | 本批涉及页面的 scenario/e2e 用例全绿；存量红（GP-01、天气线偶发）**只对账不新增** |
| 视觉 | 390 真机截图对照（本批页面全部路由）；375 人工抽查；状态四态各抽查一页 |
| 隔离 | 不触碰 `cloudfunctions/`；不触碰他人在途文件；实验目录不回灌 |
| 记录 | 三态清单 + 证据路径（截图/读数）入库 |

## 5. 后续 Agent 实施边界（可直接执行的口径）

- **默认隔离**：新 worktree（如 `d:/OurTrail-ui-<batch>`），从主工作区当前基线切出；不 fetch/push；不与其他 wave 冲突。
- **文件所有权**：P0 的 app.wxss 与全局类改动为该批独占；面板组件改动（roster/transport/field）归 P3 独占；天气三页归 P4 独占。
- **先行冻结**：动 P3 前冻结 trip2/golden-path 读数；动 P4 前冻结 weather-page-test 189 条——冻结 = 记录当前读数并声明「只对账不新增」。
- **素材**：实验室 `prototype/screenshots/` 与 `docs/ui-design/visual-direction-lab/` 为只读参照；**原型代码不进生产**（Web ≠ WXML/WXSS，需按 §1 规范重写）。
- **禁止项**：批量替换全局样式前必须有 P0 冻结；禁止用演示数据替换真实数据；禁止为视觉删减业务信息。
